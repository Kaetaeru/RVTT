# RVTT 문서 수명주기와 Discontinuation 정책

- 상태: 확정
- 문서 종류: Documentation Policy
- 즉시 구현 명세 가능성: READY
- 작성일: 2026-08-04

이 문서는 오래되거나 대체되어 현재 판단에 사용할 수 없는 문서를 권위 경로에서 제거하고, 역사 기록으로 안전하게 보존하는 규칙을 정의한다.

## 1. 문서 상태

```text
ACTIVE
→ 현재 기획·구현 판단에 사용할 수 있다.

SUPERSEDED
→ 더 최신 문서가 같은 책임을 인계했다.
→ 대체 문서가 명확하며, 제한적인 역사 비교 가치가 있다.

DISCONTINUED
→ 현재 판단에 사용하면 안 된다.
→ 전제가 폐기되었거나, 결론이 최신 구조와 충돌하거나, 유지할 실익이 없다.

ARCHIVED
→ 활성 문서 트리에서 제거되어 archive 아래에만 존재한다.
```

`SUPERSEDED`와 `DISCONTINUED`는 다르다.

- `SUPERSEDED`: 새 권위 문서가 직접 책임을 이어받는다.
- `DISCONTINUED`: 문서 자체의 판단 틀이나 목적이 더 이상 유효하지 않다.

## 2. DISCONTINUED 판정 기준

다음 중 하나 이상이면 `DISCONTINUED` 후보로 판정한다.

1. 문서가 `MISSING`, `BLOCKED`, `CONFLICT`라고 판단한 항목이 이후 권위 문서와 ADR로 해결되었다.
2. 문서의 핵심 전제가 폐기된 제품 결정에 의존한다.
3. 최신 Architecture·System 계약과 용어·권위 경계가 달라 현재 구현 판단에 사용할 수 없다.
4. 동일한 역할의 최신 Audit나 Guide가 있으며, 기존 문서를 유지하면 오히려 혼동을 만든다.
5. 마이그레이션·일회성 작업이 완료되어 현재 운영 절차로 사용할 의미가 없다.
6. 본문을 갱신하는 것보다 새 문서로 다시 작성하는 편이 정확하고 비용이 낮다.

단순히 작성일이 오래됐다는 이유만으로 폐기하지 않는다.

## 3. 판정 절차

```text
후보 발견
→ 최신 ADR·Architecture·System·Spec 확인
→ 문서의 현재 사용처와 링크 확인
→ SUPERSEDED 또는 DISCONTINUED 판정
→ 대체 문서·보관 이유 기록
→ archive/discontinued에 기록 생성
→ 활성 경로를 짧은 안내문으로 교체하거나 제거
→ README·Guide·Audit 인덱스 갱신
→ 상대 링크와 자동 검증 확인
```

두 개 이상의 문서를 한 번에 폐기할 때는 먼저 체크리스트를 작성한다.

## 4. 보관 위치

```text
docs/remake/archive/discontinued/<기존 영역>/<파일명>
```

예시:

```text
docs/remake/archive/discontinued/audits/old-foundation-audit.md
```

보관 문서에는 반드시 다음을 적는다.

```markdown
- 상태: DISCONTINUED
- 원래 경로:
- 폐기 판정일:
- 폐기 이유:
- 대체 문서:
- 마지막 유효 범위:
```

Git 기록만으로 원문 보존이 충분하면 보관 파일은 전체 본문을 복제하지 않고 역사 기록과 대체 문서만 정리할 수 있다.

## 5. 활성 경로 처리

다른 문서가 이전 경로를 참조할 가능성이 높으면 즉시 삭제하지 않고 짧은 안내문을 남긴다.

```markdown
# Discontinued

이 문서는 현재 판단에 사용할 수 없다.
보관 기록: ...
최신 권위 문서: ...
```

모든 참조가 정리되고 자동 검증으로 확인되면 안내문도 제거할 수 있다.

안내문은 권위 문서나 Audit로 취급하지 않는다.

## 6. 권위와 검색 규칙

- `archive/`와 `DISCONTINUED` 문서는 권위 우선순위에서 제외한다.
- 새 기획을 시작할 때 검색 결과에 폐기 문서가 나오면 대체 문서를 먼저 읽는다.
- 폐기 문서의 결론을 현재 `BLOCKED` 근거로 재사용하지 않는다.
- 역사적 결정 이유를 조사할 때만 폐기 문서를 참고한다.
- Guide의 Authority Documents에는 폐기 문서를 넣지 않는다.

## 7. 정기 정리

다음 시점에 Discontinuation 검사를 수행한다.

- 새로운 상위 Architecture 계약을 확정한 직후
- 오래된 Audit의 핵심 항목이 모두 해결된 직후
- 대규모 문서 이동·폴더 개편이 끝난 직후
- 구현 명세 단계로 내려가기 직전
- Main System Guide 작성 직전

검사 결과는 새 Audit 또는 archive 인덱스에 기록한다.

## 8. 금지 사항

- 최신 대체 문서를 확인하지 않고 오래된 문서를 삭제하지 않는다.
- ADR을 단순히 오래됐다는 이유로 폐기하지 않는다. ADR은 상태를 `superseded`로 바꾸고 후속 ADR을 연결한다.
- 원문과 대체 문서 사이의 관계를 기록하지 않은 채 이동하지 않는다.
- 폐기 문서를 활성 README의 권위 문서 목록에 남기지 않는다.
- 역사 기록을 이유로 같은 본문을 활성 경로와 archive에 장기간 중복 유지하지 않는다.
