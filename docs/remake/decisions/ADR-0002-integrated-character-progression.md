# ADR-0002: 통합 캐릭터 시트와 레벨 진행 시스템

- 상태: 확정
- 결정일: 2026-08-03
- 관련 결정: ADR-0001 정식 규칙 콘텐츠 직접 구현

## 배경

기존 RVTT에서는 토큰과 전투 기능을 중심으로 개발하고, 캐릭터 시트와 성장 과정은 외부 도구나 수동 입력에 의존할 수 있었다.

새 RVTT는 발더스 게이트와 같은 게임형 사용 경험을 목표로 한다. 플레이어는 외부 시트에서 수치를 옮겨 적거나, 레벨업 때 새 특성을 직접 만들어 넣지 않는다. 캐릭터 생성, 직업 선택, 하위직업 선택, 레벨별 특성 획득, 주문 습득과 준비, 자원 증가, 능력치 상승이 모두 RVTT 안에서 처리되어야 한다.

## 결정

RVTT는 캐릭터의 전체 생애주기를 직접 관리한다.

캐릭터 시트는 단순한 정보 표시 UI가 아니라 캐릭터의 영구 상태와 성장 기록을 관리하는 핵심 시스템이다. 전투 중 사용할 수 있는 행동, 주문, 반응, 자원, 패시브 효과는 시트와 성장 기록으로부터 자동으로 도출된다.

지원 목표는 다음과 같다.

1. 캐릭터 생성
2. 1레벨부터 20레벨까지의 성장
3. 모든 지원 직업의 레벨별 특성
4. 모든 지원 하위직업과 하위직업 특성
5. 종족 또는 종 특성
6. 배경과 숙련
7. 능력치, 기술, 내성 굴림, 숙련 보너스
8. 주문 습득, 주문 준비, 주문 슬롯과 주문 자원
9. 능력치 향상과 재주 선택
10. 장비, 방어도, 무기, 인벤토리와 조율
11. 체력, 임시 체력, 히트 다이스, 죽음 내성
12. 짧은 휴식과 긴 휴식
13. 다중직업
14. 선택형 직업 특성
15. 캐릭터 시트와 3D 토큰의 실시간 연결
16. DM의 검토, 승인, 수정과 예외 처리

규칙 기준이 되는 D&D 판본과 출처 목록은 별도 결정으로 고정한다. 서로 다른 판본의 규칙을 한 캐릭터 안에서 무분별하게 섞지 않는다.

## 제품 원칙

### 시트가 원본이다

캐릭터의 AC, 최대 HP, 이동속도, 공격 보너스, 주문 내성 DC, 사용 가능한 행동은 개별 UI나 토큰에 중복 저장하지 않는다.

영구 선택과 현재 상태를 바탕으로 계산해 표시한다.

예시:

- 힘 능력치와 숙련, 장비 상태로 근접 공격 보너스 계산
- 직업 레벨과 능력치로 주문 내성 DC 계산
- 갑옷, 방패, 특성, 상태 효과로 AC 계산
- 직업 레벨과 하위직업으로 사용 가능한 특성 부여
- 준비된 주문으로 주문 행동 목록 구성

### 레벨업은 검증된 절차다

레벨 숫자만 올리는 방식으로 구현하지 않는다.

레벨업은 다음 순서의 하나의 작업 단위로 처리한다.

1. 올릴 직업 선택
2. 다중직업 조건 검사
3. 새 레벨에서 얻는 고정 특성 표시
4. 하위직업, 전투 방식, 전문화, 숙련 등 선택 사항 표시
5. 능력치 향상 또는 재주 선택
6. 새 주문 습득, 교체 또는 준비
7. HP 증가 방식 선택
8. 변화 결과 미리보기
9. 규칙 검증
10. 최종 확정 및 저장

확정 전에는 캐릭터에 일부 결과만 적용되지 않는다. 실패하거나 취소하면 이전 상태를 그대로 유지한다.

### 획득한 특성은 즉시 기능이 된다

레벨업으로 `추가 공격`을 얻으면 공격 행동의 실행 횟수가 바뀐다.

`암습`을 얻으면 조건 검사와 턴당 사용 상태가 전투 시스템에 연결된다.

`격노`를 얻으면 행동창에 격노가 추가되고, 사용 횟수와 피해 보너스, 저항, 종료 조건이 연결된다.

`메타매직`을 얻으면 주문 사용 중 메타매직 선택 단계가 나타난다.

특성 이름과 설명만 시트에 추가하고 실제 행동은 수동으로 처리하는 것을 기본 방식으로 삼지 않는다.

### 수동 수정은 예외 수단이다

DM은 체력, 능력치, 자원, 장비, 획득 특성을 직접 수정할 수 있다. 그러나 정상적인 캐릭터 생성과 레벨업은 정해진 규칙 절차를 통해 이루어져야 한다.

수동 수정은 홈브루, 세션 중 판정, 데이터 복구, 특수 보상에 사용하는 관리자 기능이다.

## 캐릭터 데이터 구조

캐릭터 데이터는 다음 계층으로 나눈다.

### 1. 정체성과 영구 선택

- 캐릭터 이름과 외형
- 종족 또는 종
- 배경
- 직업별 레벨
- 하위직업
- 능력치 생성 결과
- 숙련과 언어
- 재주
- 직업 및 하위직업 선택 사항
- 습득한 주문
- 장비와 소유 아이템

### 2. 성장 기록

각 레벨에서 어떤 선택을 했는지 순서대로 보존한다.

예시:

- 캐릭터 1레벨 생성
- 전사 2레벨 획득
- 전사 3레벨에서 전투의 대가 선택
- 전사 4레벨에서 재주 선택
- 이후 마법사 1레벨 다중직업

최종 결과만 저장하지 않고 성장 기록을 남겨야 레벨업 검증, 재계산, 규칙 변경 대응, 되돌리기가 가능하다.

### 3. 계산된 시트 값

다음 값은 영구 데이터에서 계산한다.

- 최대 HP
- AC
- 이동속도
- 우선권
- 숙련 보너스
- 기술과 내성 보너스
- 공격 보너스와 피해식
- 주문 공격 보너스와 주문 내성 DC
- 주문 슬롯
- 특성 사용 횟수
- 운반 한도
- 감각과 시야

필요한 경우 계산 결과를 캐시할 수 있지만 원본으로 취급하지 않는다.

### 4. 현재 세션 상태

- 현재 HP와 임시 HP
- 소비된 주문 슬롯
- 소비된 직업 자원
- 현재 상태이상
- 집중 중인 주문
- 죽음 내성 결과
- 장착 상태
- 짧은 휴식 또는 긴 휴식 이후 회복 상태

영구 성장 데이터와 분리하여 저장한다.

## 핵심 시스템 경계

### RulesContentCatalog

직업, 하위직업, 레벨별 특성, 주문, 종족, 배경, 재주, 장비의 정식 정의를 제공한다.

### CharacterBuildService

새 캐릭터 생성 과정과 선택 가능한 항목을 관리한다.

### AdvancementService

레벨업, 다중직업, HP 증가, 특성 선택, 주문 습득을 검증하고 하나의 작업으로 적용한다.

### CharacterDerivationService

영구 선택, 장비, 현재 효과를 바탕으로 시트 수치와 획득 능력을 계산한다.

### AbilityGrantService

캐릭터가 획득한 특성, 주문, 장비 행동을 실제 실행 가능한 능력으로 연결한다.

### CharacterStateService

HP, 자원, 주문 슬롯, 휴식, 죽음 내성, 상태 효과 등 현재 상태를 관리한다.

### CharacterSheetController

플레이어에게 시트를 보여주며, 편집 가능한 항목과 계산된 항목을 구분한다.

### ActorBindingService

캐릭터 시트와 월드의 토큰을 연결한다. 하나의 캐릭터가 다른 장면에 배치되어도 같은 캐릭터 상태를 사용한다.

## 캐릭터 시트 UI 범위

시트는 최소한 다음 화면을 가진다.

1. **요약** — 능력치, HP, AC, 이동속도, 숙련, 감각
2. **행동** — 행동, 보너스 행동, 반응, 자유 행동, 특수 행동
3. **특성** — 직업, 하위직업, 종족, 재주, 패시브
4. **주문** — 주문 목록, 준비 상태, 슬롯, 집중, 주문 능력치
5. **인벤토리** — 장비, 소모품, 화폐, 조율
6. **숙련** — 기술, 내성, 무기, 방어구, 도구, 언어
7. **성장** — 직업 레벨, 하위직업, 레벨별 획득 기록
8. **상태** — 현재 효과, 상태이상, 자원, 휴식 회복 항목
9. **설명** — 배경, 성격, 메모와 캐릭터 정보

전투 중에는 전체 시트를 항상 열 필요가 없도록, 시트에서 도출된 행동을 별도의 빠른 행동창에도 제공한다.

## 모든 기능 구현의 의미

`모든 기능`은 모든 규칙을 하나의 범용 설정 파일로 표현한다는 뜻이 아니다.

각 직업과 하위직업은 정식 콘텐츠 패키지로 구현한다. 반복되는 규칙은 공통 엔진을 사용하고, 독특한 특성은 전용 처리기를 가진다.

예시:

- 전사 패키지: 전투 방식, 재기의 바람, 행동 연쇄, 추가 공격, 불굴
- 야만용사 패키지: 격노, 무모한 공격, 위험 감지, 원시의 길
- 도적 패키지: 암습, 교활한 행동, 전문화, 회피, 믿을 수 있는 재능
- 마법사 패키지: 주문책, 주문 준비, 비전 회복, 비전 전통

하위직업은 부모 직업의 진행 체계 위에 추가 특성과 선택을 제공한다.

## 구현 가능성

기술적으로 가능하다.

Roblox의 기능이나 데이터 구조 때문에 불가능한 범위는 아니다. 어려운 부분은 엔진 자체보다 방대한 규칙 콘텐츠를 정확하게 구현하고 시험하는 작업량이다.

따라서 최종 목표는 전체 직업, 하위직업, 레벨 구간을 지원하는 것으로 유지하되 다음 방식으로 진행한다.

1. 캐릭터 데이터와 계산 엔진을 먼저 완성한다.
2. 캐릭터 생성과 레벨업 절차를 먼저 완성한다.
3. 무술 직업과 주문 직업을 각각 하나씩 끝까지 구현해 구조를 검증한다.
4. 직업을 하나씩 완성된 패키지 단위로 추가한다.
5. 직업마다 하위직업과 관련 주문, 재주, 장비를 함께 시험한다.
6. 완료되지 않은 직업을 부분적으로 공개하지 않고 지원 범위를 명확히 표시한다.

## 결과

RVTT는 더 이상 전투 맵 위에 수동 캐릭터 시트를 붙인 도구가 아니다.

캐릭터 생성, 성장, 시트, 행동, 전투, 휴식이 하나의 규칙 시스템으로 연결된 D&D 게임형 VTT가 된다.

플레이어가 레벨업하면 시트의 숫자만 바뀌는 것이 아니라 새 특성, 선택지, 자원, 주문, 행동이 실제 게임 기능으로 활성화된다.
