# ADR-0004: DM이 있는 발더스 게이트형 세션 조작

- 상태: 확정
- 결정일: 2026-08-03
- 관련 결정:
  - ADR-0001 정식 규칙 콘텐츠 직접 구현
  - ADR-0002 통합 캐릭터 시트와 레벨 진행 시스템
  - ADR-0003 D&D 2024, 출처 팩과 다국어 구조

## 배경

RVTT가 지향하는 사용 경험을 단순히 "3D VTT"라고만 정의하면 카메라, 이동, 상호작용과 전투 UI가 서로 다른 방향으로 구현될 수 있다.

새 RVTT의 목표는 플레이어가 복잡한 VTT 조작법을 배우는 대신, 발더스 게이트와 같은 전술 RPG를 플레이하듯 캐릭터를 움직이고 행동하게 하는 것이다. 동시에 세션에는 DM이 존재하며, DM이 장면, 판정, NPC, 정보 공개와 예외를 통제한다.

## 결정

RVTT의 수면 위 사용 경험을 다음 문장으로 정의한다.

> RVTT는 DM이 실시간으로 진행하는 발더스 게이트형 D&D 세션이다.

이는 특정 게임의 화면을 그대로 복제한다는 의미가 아니다. 다음 경험을 제품의 기준점으로 삼는다는 뜻이다.

- 자유롭게 전장을 살펴보는 전술 카메라
- 캐릭터를 선택하고 이동 목적지와 행동 대상을 직관적으로 지정
- 이동 경로, 사거리, 범위와 유효 여부를 실행 전에 확인
- 캐릭터 시트에서 도출된 행동, 주문과 특성을 바로 사용
- 탐험과 전투가 같은 3D 장면에서 자연스럽게 전환
- 자동화 가능한 규칙은 게임처럼 처리하고, 해석이 필요한 부분은 DM이 판정

## 1. 기본 공간 단위

이동 가능한 맵 표면에는 기본적으로 **5피트 × 5피트 논리 격자**가 존재한다.

```text
1 cell = 5 ft × 5 ft
```

격자는 다음에 사용한다.

- 토큰의 점유 위치
- 이동 경로와 거리
- 주문과 특성의 사거리
- 범위 효과
- 엄폐와 시야 판정의 기준점
- 위험 지역과 지형 효과
- 전투 중 남은 이동력

격자는 맵 전체 경계에 무조건 생성되는 평면이 아니라, 실제로 이동할 수 있는 각 표면에 정의된다. 바닥, 계단, 다리와 여러 높이의 이동 가능 표면은 각자의 탐색 가능한 셀을 가진다.

### 격자 표현

논리 격자가 존재한다고 해서 각 칸을 Roblox Part로 만들지 않는다.

- 격자는 내비게이션 데이터로 관리한다.
- 화면에는 현재 카메라 주변, 선택한 토큰 주변, 이동 경로와 범위처럼 필요한 부분만 표시한다.
- 탐험 중에는 격자를 흐리게 하거나 숨길 수 있다.
- 전투 중에는 이동과 대상 지정에 필요한 격자를 명확하게 표시한다.

## 2. 자유 전술 카메라

플레이어와 DM은 토큰에 고정되지 않은 자유 전술 카메라를 사용한다.

기본 기능은 다음과 같다.

- 화면 이동
- 회전
- 확대와 축소
- 높이 조절
- 선택한 토큰으로 초점 이동
- 선택한 토큰 추적 켜기와 끄기
- 시야를 가리는 구조물의 가시성 보정

카메라 위치는 캐릭터의 실제 위치나 권한을 바꾸지 않는다. 플레이어가 카메라를 옮겼다고 해서 캐릭터가 볼 수 없는 비공개 정보가 공개되어서는 안 된다.

## 3. 두 가지 이동 입력 방식

플레이어는 자신의 선호에 따라 두 이동 방식을 사용할 수 있다.

### 3.1 클릭 이동

1. 캐릭터를 선택한다.
2. 목적 셀에 마우스를 올린다.
3. 예상 이동 경로, 거리와 도달 가능 여부를 본다.
4. 목적지를 클릭한다.
5. 서버가 이동을 검증한다.
6. 캐릭터가 경로를 따라 이동한다.

탐험에서는 유효한 목적지까지 연속 이동한다. 전투에서는 남은 이동력과 지형 비용 안에서만 이동할 수 있다.

### 3.2 WASD 직접 이동

선택한 캐릭터를 WASD로 직접 움직인다.

- 입력은 논리 격자의 인접 셀 이동으로 변환한다.
- 화면에서는 셀 사이를 부드럽게 보간하여 움직인다.
- 이동할 때마다 동일한 충돌, 경로, 권한과 이동 비용 검증을 거친다.
- 카메라는 선택한 캐릭터를 따라가거나 사용자가 분리할 수 있다.

직접 이동은 물리 기반 자유 보행으로 별도 구현하지 않는다. 클릭 이동과 다른 규칙을 사용하면 거리, 충돌과 전투 이동 결과가 달라지기 때문이다.

### 3.3 입력 방식 전환

클릭 이동과 WASD 이동은 서로 다른 세션 모드가 아니다.

- 플레이어 개인의 조작 설정이다.
- 탐험과 전투 모두에서 사용할 수 있다.
- 한 번의 단축키 또는 설정으로 전환할 수 있다.
- 전환해도 캐릭터 위치, 경로와 남은 이동력이 바뀌지 않는다.

클릭 이동 모드에서는 WASD를 카메라 이동에 사용할 수 있다. WASD 직접 이동 모드에서는 별도의 카메라 드래그, 화면 가장자리 이동 또는 카메라 수정 입력을 사용한다. 구체적인 키 배치는 UI·입력 문서에서 정한다.

## 4. 단일 이동 파이프라인

두 입력 방식은 같은 이동 시스템을 사용한다.

```text
사용자 입력
→ 이동 의도 생성
→ 시작 셀과 목적 셀 확인
→ 경로 탐색
→ 이동 비용 계산
→ 클라이언트 미리보기
→ 서버 재검증
→ 확정 경로 실행
→ 위치와 이동력 갱신
→ 다른 참가자에게 결과 동기화
```

서버는 최소한 다음을 검증한다.

- 해당 플레이어가 토큰을 조작할 권한이 있는가
- 시작 위치가 서버 상태와 일치하는가
- 각 셀이 이동 가능한가
- 문, 오브젝트와 토큰에 막히지 않는가
- 높이 차이와 연결 경로가 유효한가
- 전투 중 남은 이동력이 충분한가
- 현재 상태 효과가 이동을 허용하는가
- 이동 중 새 장애물이나 상태 변화가 발생하지 않았는가

## 5. 탐험과 전투에서의 차이

### 탐험

- 턴과 이동력 제한 없이 이동한다.
- DM이 이동을 잠그거나 특정 캐릭터만 허용할 수 있다.
- 이동 중 상호작용 지점, 위험 지역과 이벤트가 경로를 중단할 수 있다.
- 캐릭터가 발견하지 못한 비밀 정보는 카메라 위치와 무관하게 숨긴다.

### 전투

- 현재 턴과 조작 권한을 확인한다.
- 셀별 이동 비용을 남은 이동력에서 소비한다.
- 이동 경로와 소비량을 실행 전에 표시한다.
- 이동 도중 발생하는 반응 행동과 위험을 처리한다.
- 이동을 나누어 행동 전후에 사용할 수 있다.

두 모드의 차이는 입력기가 아니라 규칙 제약이다.

## 6. DM 조작

DM은 자유 카메라로 전체 장면을 살펴보고, 자신이 통제하는 NPC와 몬스터를 플레이어와 동일한 이동 체계로 조작한다.

DM에게는 다음과 같은 별도 권한 동작을 제공할 수 있다.

- 강제 이동
- 순간이동
- 위치 복구
- 숨겨진 토큰 이동
- 여러 토큰 동시 배치

이 동작은 일반 이동과 구분하고 로그에 남긴다. DM 권한이 있다는 이유로 일반 이동 검증과 강제 조작을 같은 함수에 뒤섞지 않는다.

## 7. 상호작용 감각

선택과 이동은 다음 피드백을 제공한다.

- 선택한 캐릭터의 명확한 표시
- 마우스를 올린 셀과 오브젝트 강조
- 이동 경로와 거리 표시
- 도달 불가 지점의 이유 표시
- 상호작용 가능한 오브젝트의 문맥 행동
- 클릭한 목적지에 대한 즉각적인 입력 피드백
- 서버 거부 시 위치 복구와 이해 가능한 사유 표시

## 8. 비목표

- 발더스 게이트의 UI, 아트와 자산을 그대로 복제하지 않는다.
- 탐험용 이동과 전투용 이동을 별도 게임으로 만들지 않는다.
- WASD 이동을 Roblox 캐릭터 물리와 Humanoid의 무제한 자유 이동에 맡기지 않는다.
- 격자 한 칸마다 물리 Part와 개별 스크립트를 생성하지 않는다.
- 카메라 이동으로 비공개 정보와 시야 제한을 우회하지 못하게 한다.

## 결과

이 결정으로 카메라, 탐험, 전투, 경로 탐색과 상호작용 UI는 하나의 제품 방향을 공유한다.

조작 방식은 두 가지지만 규칙과 상태는 하나이므로, 기능 차이와 버그 중복을 줄일 수 있다. 논리 격자와 필요한 부분만 표시하는 방식은 대형 장면에서도 성능을 유지하는 기반이 된다.
