# ADR-0006: 리그 없는 3D 토큰의 연속 이동

- 상태: 확정
- 결정일: 2026-08-03
- 대체 범위: ADR-0004의 5피트 고정 격자 이동, 격자 셀 기반 WASD와 이동 파이프라인
- 유지 범위: ADR-0004의 발더스 게이트형 세션 경험, 자유 전술 카메라, 클릭·WASD 입력 지원
- 관련 결정:
  - ADR-0004 DM이 있는 발더스 게이트형 세션 조작
  - ADR-0005 성능, 안정성과 클린코드를 필수 기능으로 취급

## 배경

RVTT의 캐릭터와 몬스터는 Roblox 플레이어 아바타가 아니다. 외부에서 가져온 OBJ 또는 MeshPart 기반의 3D 미니어처 토큰으로 표현한다.

이 토큰은 리그와 걷기 애니메이션을 전제로 하지 않는다. 따라서 Roblox 캐릭터용 이동 상태, 관절, 애니메이터와 물리 보행을 제공하는 Humanoid를 이동 기반으로 사용할 필요가 없다.

또한 발더스 게이트형 자유 이동을 목표로 하면서 모든 위치를 5피트 격자 중심에 고정하면 곡선 통로, 계단, 다리, 엄폐물 주변과 세밀한 위치 조작이 부자연스러워진다.

## 결정

RVTT는 **리그 없는 3D 토큰을 스크립트로 이동시키는 연속 이동 방식**을 사용한다.

### 1. 토큰 표현

토큰은 다음 책임만 가진다.

- 3D 외형
- 위치와 회전의 기준이 되는 루트 또는 피벗
- 선택 표시와 규칙용 점유 범위
- 토큰 ID와 표시 상태

토큰의 메시 모양, 검, 망토, 날개와 장식은 이동 충돌이나 점유 판정에 사용하지 않는다.

Roblox 기본 캐릭터, 플레이어 아바타, Humanoid와 Animator는 기본 토큰 이동 구조에 포함하지 않는다.

### 2. 비물리적 이동

토큰의 확정 위치는 물리 엔진의 밀기, 넘어짐과 충돌 반응에 맡기지 않는다.

이동 시스템이 승인한 경로를 따라 토큰 모델의 피벗을 부드럽게 갱신한다. 화면에서는 연속적으로 이동하지만, 위치와 이동 결과의 최종 권한은 서버가 가진다.

토큰끼리 물리적으로 밀어내지 않는다. 다른 토큰, 벽과 장애물을 통과할 수 있는지는 별도의 이동 판정이 결정한다.

### 3. 연속 좌표와 피트 단위

토큰은 이동 가능한 표면 위의 연속 좌표에 위치할 수 있다. 기본 이동은 5피트 칸 중심에 스냅하지 않는다.

D&D 규칙의 거리 단위는 그대로 피트를 사용한다.

예시:

- 이동속도 30피트
- 근접 사거리 5피트
- 주문 사거리 60피트
- 범위 반경 20피트

5피트 격자는 거리 확인, 맵 제작과 전술적 가독성을 위한 선택적 시각 오버레이다. 격자 표시 여부가 실제 이동 가능 위치를 제한하지 않는다.

### 4. 클릭 이동과 WASD 이동

두 입력 방식은 같은 이동 판정과 실행 시스템을 사용한다.

#### 클릭 이동

```text
목적지 지정
→ 경로와 이동 비용 미리보기
→ 이동 요청
→ 서버 검증
→ 승인된 경로를 따라 토큰 이동
```

#### WASD 이동

```text
입력 방향
→ 짧은 이동 의도 생성
→ 다음 위치와 이동 비용 검사
→ 서버 검증
→ 토큰 위치를 연속적으로 갱신
```

WASD가 별도의 물리 캐릭터 컨트롤러가 되지 않는다. 클릭 이동과 WASD 이동은 동일한 이동 가능 표면, 차단물, 토큰 점유, 험지와 상태 효과를 사용한다.

### 5. 규칙용 점유 범위

각 토큰은 모델 외형과 분리된 단순한 규칙용 점유 범위를 가진다.

점유 범위는 다음에 사용한다.

- 좁은 문과 통로 통과 여부
- 다른 토큰과의 겹침
- 벽과 장애물과의 간격
- 근접 거리와 위협 범위
- 범위 효과와 대상 포함 여부

정확한 점유 모양과 크기별 수치는 후속 이동 판정 문서에서 확정한다.

### 6. 중앙 이동 시스템

토큰마다 개별 이동 스크립트와 매 프레임 루프를 두지 않는다.

중앙 이동 시스템은 현재 실제로 이동 중인 토큰만 갱신한다. 정지한 토큰은 지속적인 이동 계산을 하지 않는다.

책임은 다음처럼 분리한다.

- 입력: 클릭과 WASD를 이동 의도로 변환
- 경로: 목적지까지의 유효 경로 생성
- 비용: 거리, 험지와 이동 상태 계산
- 검증: 권한, 차단, 점유와 남은 이동력 확인
- 실행: 승인된 토큰 피벗 이동
- 동기화: 확정 위치와 이동 상태 전달

### 7. 서버 권한

클라이언트는 이동 미리보기와 부드러운 표시를 담당할 수 있지만 다음을 확정하지 않는다.

- 이동 가능한 위치
- 이동 거리와 비용
- 벽과 토큰 통과 여부
- 전투 중 남은 이동력
- 이동으로 발생하는 반응과 위험
- 최종 토큰 위치

서버는 이동 시작점, 경로, 목적지와 현재 장면 상태를 검증한 뒤 결과를 확정한다.

## 성능상의 결과

Humanoid, 리그, 애니메이션 상태와 물리 보행을 사용하지 않으므로 토큰 하나당 관리해야 하는 런타임 상태가 줄어든다.

- 정지한 토큰에는 이동 업데이트가 필요 없다.
- 토큰끼리 물리 충돌을 계산하지 않는다.
- 메시의 복잡한 형태를 충돌 판정에 사용하지 않는다.
- 중앙 시스템이 활성 이동만 처리한다.
- 이동 가능 여부는 장면의 별도 내비게이션 데이터에서 판정한다.

이 구조는 다수의 정적인 3D 토큰이 존재하는 RVTT의 사용 방식에 적합하다.

## 코드상의 결과

토큰 외형, 이동 규칙과 장면 판정을 분리할 수 있다.

- 외형을 바꾸어도 이동 규칙이 바뀌지 않는다.
- 이동 오류를 입력, 경로, 비용, 검증과 표시 단계로 나누어 찾을 수 있다.
- 플레이어 토큰과 몬스터 토큰이 같은 이동 코드를 사용한다.
- 클릭과 WASD의 규칙 코드가 중복되지 않는다.
- 물리 엔진의 예외 상태를 D&D 규칙과 혼합하지 않는다.

## 비목표

- 모든 토큰에 걷기 애니메이션을 제공하지 않는다.
- Roblox 캐릭터 컨트롤러를 토큰 조작에 재사용하지 않는다.
- 토큰 메시의 실제 외곽을 정밀 충돌체로 사용하지 않는다.
- 클릭 이동과 WASD 이동을 서로 다른 규칙 엔진으로 구현하지 않는다.
- 격자 이동과 연속 이동을 동시에 별도 시스템으로 유지하지 않는다.

## 후속 결정

이 ADR은 토큰 이동 방식만 확정한다. 다음 항목은 장면과 이동 판정 기획에서 결정한다.

- 이동 가능한 표면의 표현 방식
- 벽, 구조물과 동적 차단물
- 투명 연출 파트와 내비게이션 제외 방식
- 험지와 이동 비용 영역
- 계단, 경사, 사다리와 층간 연결
- 경로 탐색 데이터 구조
- 정적 데이터 사전 계산과 런타임 갱신 방식
