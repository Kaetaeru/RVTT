# ADR-0013: 플레이어당 단일 캐릭터와 씬 소속 NPC 분리

- 상태: 확정
- 결정일: 2026-08-03
- 관련 문서:
  - [`ADR-0011`](ADR-0011-persistent-character-runtime-state.md)
  - [`ADR-0012`](ADR-0012-campaign-scoped-character-ownership.md)
  - [`04-scenes-and-world.md`](../04-scenes-and-world.md)

## 배경

RVTT에는 장기간 성장하고 캠페인 전체에서 유지되는 플레이어 캐릭터와, 특정 장면에서 등장하며 스탯블록을 사용하는 NPC가 함께 존재한다.

두 대상을 같은 데이터형으로 취급하면 다음 문제가 생긴다.

- NPC가 플레이어의 캐릭터 슬롯을 차지함
- 캐릭터 성장과 NPC 스탯블록 규칙이 섞임
- 씬에서만 필요한 NPC 상태가 캠페인 전역 데이터에 누적됨
- 캐릭터 저장과 씬 저장의 책임 경계가 불명확해짐

## 결정

### 1. 플레이어당 캠페인 캐릭터는 최대 한 명이다

한 캠페인에서 한 플레이어 계정에 배정할 수 있는 플레이어 캐릭터는 최대 한 명이다.

```text
Campaign Member
└─ characterId: CharacterId?
```

캐릭터 생성 전이거나 캐릭터가 제거된 상태를 허용하기 위해 `0명 또는 1명`으로 표현한다.

한 플레이어가 같은 캠페인에서 여러 플레이어 캐릭터를 보유하거나 전환하는 기능은 기본 범위에 포함하지 않는다.

DM 관리 권한은 이 제한과 별개다. DM은 캠페인 관리자로서 여러 캐릭터 데이터를 열람하고 수정할 수 있지만, 이것이 DM 계정에 여러 플레이어 캐릭터가 소속된다는 뜻은 아니다.

### 2. 플레이어 캐릭터와 스탯블록 NPC는 서로 다른 엔티티다

플레이어 캐릭터와 NPC는 공통 토큰 표현이나 일부 전투 계산을 공유할 수 있지만 저장 데이터의 원본과 생명주기는 분리한다.

```text
Character
→ 캠페인 소속
→ 종, 배경, 직업, 레벨과 성장 기록
→ 캠페인 전체에서 유지되는 인벤토리와 현재 상태

SceneNpc
→ 씬 소속
→ 스탯블록 기반 능력과 현재 상태
→ 해당 씬의 저장, 복제와 삭제 생명주기를 따름
```

NPC를 플레이어 캐릭터로 위장하거나 캐릭터 스키마에 NPC용 예외 필드를 계속 추가하지 않는다.

### 3. 캐릭터 보유와 NPC 조작 권한은 독립적이다

플레이어가 자신의 캠페인 캐릭터를 가지고 있더라도 현재 씬의 NPC를 추가로 조작할 수 있다.

```text
Player
├─ Campaign Character: 최대 1명
└─ Controlled Scene NPCs: 0명 이상
```

NPC 조작 권한은 캐릭터 슬롯을 사용하지 않는다.

예시:

- 플레이어 캐릭터와 소환수 NPC 조작
- 플레이어 캐릭터와 임시 동료 NPC 조작
- 캐릭터 없이 특정 NPC만 조작
- DM이 여러 NPC를 직접 조작

정확한 동시 선택과 턴 UI는 후속 입력·전투 기획에서 정의한다.

## 씬 NPC 데이터 소유권

NPC 인스턴스 데이터는 해당 씬의 원본 데이터에 저장한다.

개념 구조:

```text
Campaign
├─ Characters
└─ Scenes
   └─ Scene
      └─ Npcs
         └─ SceneNpc
```

각 `SceneNpc`는 최소한 다음을 가진다.

- 씬 안에서 고유한 `npcId`
- 소속 `sceneId`
- 사용할 스탯블록 ID 또는 씬 전용 스탯블록 데이터
- 이름과 토큰 표현
- 현재 HP, 자원과 상태 효과
- 위치와 장면 배치 상태
- 진영, 숨김과 공개 상태
- 플레이어·DM 조작 권한 배정
- 데이터 버전

재사용 가능한 기본 몬스터와 NPC 스탯블록 정의는 콘텐츠 카탈로그에서 참조할 수 있다. 그러나 그 정의로 생성된 실제 NPC 인스턴스, 현재 HP, 위치, 상태와 조작 권한은 씬 데이터가 소유한다.

씬 전용으로 수정한 스탯블록은 씬 내부 데이터 또는 명시적인 오버라이드로 저장하며, 원본 카탈로그 정의를 직접 변경하지 않는다.

## 씬 사이 이동

씬 NPC는 기본적으로 하나의 씬에 속한다.

NPC를 다른 씬에서 계속 사용하려면 다음 중 하나의 명시적 작업을 사용한다.

- NPC를 다른 씬으로 이동
- 현재 NPC를 다른 씬에 복사
- 재사용 가능한 스탯블록으로 새 NPC 생성

단순히 두 씬이 같은 `npcId`를 공유하게 하지 않는다.

이동 시에는 원본 씬에서 제거하고 대상 씬에 새 소속을 확정하는 하나의 원자적 작업으로 처리해야 한다. 정확한 이동·복사 정책은 씬 관리 명세에서 정의한다.

## 권한 검증

서버는 NPC 명령마다 최소한 다음을 확인한다.

- NPC가 현재 `sceneId`에 속하는지
- 요청 플레이어가 해당 NPC를 조작할 권한이 있는지
- 현재 세션과 전투 턴에서 해당 행동이 허용되는지
- NPC가 숨김 또는 DM 전용 대상인지
- 요청이 플레이어 캐릭터의 권한을 NPC 권한으로 오인하지 않는지

캐릭터 조작 권한을 가졌다는 이유만으로 모든 씬 NPC를 조작할 수 있게 하지 않는다.

## 저장 경계

```text
캠페인 캐릭터 저장
→ 캐릭터 생성, 성장, 인벤토리, 현재 상태

씬 저장
→ NPC 인스턴스, NPC 현재 상태, 위치, 진영과 조작 권한
```

씬을 언로드하거나 서버가 종료되어도 씬에 저장된 NPC 상태는 유지된다.

씬을 삭제하면 그 씬에만 속한 NPC도 함께 삭제 대상이 된다. 실수 방지를 위한 보관과 복구 정책은 씬 삭제 정책을 따른다.

## 결과

- 플레이어의 주인공 캐릭터 구조가 단순해진다.
- 소환수와 임시 동료를 캐릭터 슬롯과 무관하게 조작할 수 있다.
- NPC 수가 늘어나도 캠페인 캐릭터 저장소가 오염되지 않는다.
- 씬 복사, 저장과 복구가 해당 씬의 NPC까지 포함하는 명확한 단위가 된다.
- 캐릭터 성장 시스템과 스탯블록 실행 시스템을 독립적으로 발전시킬 수 있다.
