# ADR-0012: 캠페인 소속 캐릭터와 플레이어 조작 권한

- 상태: 확정
- 결정일: 2026-08-03
- 관련 문서:
  - [`ADR-0011`](ADR-0011-persistent-character-runtime-state.md)
  - [`AGENTS.md`](../../../AGENTS.md)

## 배경

RVTT의 캐릭터 데이터가 플레이어 계정에 직접 귀속되면, 같은 캐릭터를 서로 다른 캠페인에서 공유하거나 캠페인 규칙과 상태가 섞일 위험이 있다.

캐릭터의 현재 HP, 자원, 상태 효과, 장비와 성장 기록은 특정 캠페인에서 발생한 결과이므로 캠페인의 생명주기와 함께 관리해야 한다.

## 결정

캐릭터는 플레이어 계정이 아니라 **특정 캠페인에 소속되는 영구 데이터 엔티티**로 관리한다.

개념적 관계:

```text
Campaign
└─ Characters
   └─ Character
      ├─ permanent choices
      ├─ persistent runtime state
      ├─ inventory and equipment
      ├─ progression history
      └─ access assignments
```

각 캐릭터는 다음 식별자를 가진다.

- 전역적으로 고유한 `characterId`
- 반드시 하나의 `campaignId`

`campaignId`는 단순한 검색 태그가 아니라 캐릭터 데이터의 소속과 권한 경계를 결정한다.

## 플레이어와 캐릭터의 관계

플레이어 계정은 캐릭터 데이터의 상위 소유자가 아니다.

대신 캠페인 안에서 다음과 같은 접근 권한을 부여받는다.

- 소유 플레이어 또는 기본 조작자
- 추가 조작자
- 열람 권한
- DM 관리 권한

정확한 역할 이름과 다중 조작 규칙은 후속 기획에서 확정한다.

플레이어가 캠페인을 떠나도 캐릭터 데이터는 삭제되지 않는다. 접근 권한만 제거하거나 DM이 다른 플레이어에게 재배정할 수 있어야 한다.

## 권한 원칙

서버는 캐릭터 변경 요청마다 최소한 다음을 검증한다.

- 요청한 캐릭터가 현재 캠페인에 속하는지
- 요청 플레이어가 해당 캐릭터를 조작할 권한이 있는지
- 현재 세션과 장면에서 변경 가능한 상태인지
- DM 전용 변경인지

클라이언트가 보낸 `characterId`만으로 데이터 접근을 허용하지 않는다.

## 캠페인 사이 이동

캐릭터의 `campaignId`를 직접 바꾸어 다른 캠페인으로 이동시키지 않는다.

다른 캠페인에서 같은 캐릭터 구성을 사용하려면 후속 기능에서 명시적인 복사, 가져오기 또는 내보내기 흐름을 제공한다.

이 경우에도 새 캠페인에는 새로운 `characterId`를 가진 별도 캐릭터가 생성된다.

## 저장과 삭제

- 캐릭터 저장은 캠페인 데이터 경계 안에서 수행한다.
- 캠페인 보관 시 캐릭터도 함께 보관한다.
- 캠페인 삭제와 캐릭터 영구 삭제는 실수 방지를 위해 별도 정책과 확인 절차를 가진다.
- 플레이어 계정 삭제나 캠페인 탈퇴가 캐릭터 자동 삭제를 의미하지 않는다.

## 아직 확정하지 않는 사항

다음은 후속 기획에서 정한다.

- 한 플레이어가 한 캠페인에서 소유할 수 있는 캐릭터 수
- 동시에 활성화할 수 있는 캐릭터 수
- 공동 조작과 임시 대리 조작 규칙
- DM이 만든 동료 캐릭터와 일반 NPC의 데이터 경계
- 캠페인 간 캐릭터 복사·가져오기 정책
