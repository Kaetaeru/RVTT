## Context

RVTT는 DM이 실시간으로 진행하는 전술 RPG형 D&D 세션을 목표로 한다. 사용자는 메뉴를 반복해서 탐색하기보다 월드에서 Actor를 선택하고 이동·공격·상호작용을 직접 이어서 실행할 수 있어야 한다.

그러나 직접성을 높이기 위해 좌클릭에 상황별 행동을 연결하면 다음 위험이 생긴다.

- 클릭 결과가 보이지 않아 의도하지 않은 공격이나 이동이 실행된다.
- 오른쪽 클릭, 카메라와 Context Action Menu의 역할이 충돌한다.
- 사용할 수 없는 행동과 권한에 없는 행동이 같은 방식으로 숨겨져 이유를 알 수 없다.
- 행동마다 선택이 해제되거나 턴마다 카메라가 강제로 이동해 플레이 흐름이 끊긴다.
- 서버 승인 전에 클라이언트가 성공한 것처럼 보이거나, 거부 사유가 화면 중앙 모달을 남발한다.
- 숨은 대상과 DM 전용 Capability가 UI 편의를 통해 누출될 수 있다.

따라서 물리 입력, 상황별 기본 행동, 전체 행동표, Preview, 서버 권위 피드백과 선택·카메라 연속성을 하나의 상위 UX 계약으로 고정한다.

## Decision

### 1. PC 기본 포인터 문법

```text
왼쪽 클릭
→ PrimaryPointer
→ 선택 전에는 Actor 선택
→ 선택 후에는 화면에 표시된 상황별 기본 행동 요청 또는 Preview

오른쪽 클릭
→ ContextActionPointer
→ 선택 Actor와 클릭 대상 기준 전체 행동표 표시

마우스 휠 클릭 드래그
→ CameraOrbitPointer
→ 자유 전술 카메라 Yaw·Pitch 회전

Wheel
→ Camera Zoom

Ctrl+Wheel
→ Camera Pivot Y 이동

F 또는 Space
→ 선택 Actor Frame
```

오른쪽 클릭은 카메라를 회전하지 않는다. 기존 오른쪽 클릭 카메라 감각은 마우스 휠 클릭 드래그로 이동한다.

물리 버튼은 기능 코드에 직접 결합하지 않고 Semantic Action과 Input Context를 거친다.

### 2. Q와 E

```text
Q
→ 최상위 입력 문맥 하나만 닫거나 취소

E
→ 현재 Preview·선택·승인·확정 실행
```

ESC에는 Gameplay 의미를 부여하지 않는다.

Q는 한 번에 한 단계만 처리한다.

```text
Context Action Table 열림
→ Q: 표만 닫기

대상 지정 또는 Preview 진행 중
→ Q: 현재 단계만 취소하고 이전 행동 문맥으로 복귀

반복 행동 고정 중
→ Q: 반복 행동 해제

하위 문맥 없이 Actor만 선택됨
→ Q: Actor 선택 해제

취소할 문맥 없음
→ 아무 행동도 하지 않음
```

한 번의 Q로 메뉴, 대상 지정과 Actor 선택을 연속해서 모두 닫지 않는다.

### 3. 좌클릭 기본 행동

좌클릭 기본 행동은 학습 모델이나 숨은 가중치가 아니라 결정적인 우선순위로 정한다.

```text
조작 가능한 다른 아군 Actor
→ 해당 Actor로 선택 전환

적대 Actor + 활성 Encounter
→ 현재 기본 공격 또는 선택된 기본 전투 행동

우호·중립 Actor
→ 대화·도움·상호작용
→ 공격을 암묵적 기본 행동으로 사용하지 않음

Exploration Object
→ 현재 Object 상태에 맞는 기본 상호작용

이동 가능한 표면
→ 이동

유효한 기본 행동 없음
→ 실행하지 않고 이유 표시
```

다른 조작 가능한 아군을 클릭했을 때 현재 Actor의 공격이나 상호작용 대상으로 해석하지 않는다.

사용자는 Context Action Table에서 행동을 명시적으로 기본 행동으로 지정할 수 있다. 최근 사용 행동만으로 기본값을 자동 변경하지 않는다. 지정된 행동이 현재 불가능하면 안전한 상황 기본 행동으로 돌아간다.

### 4. 클릭 전 결과 가시성

좌클릭으로 실행될 행동은 클릭 전에 보여야 한다.

즉시 표시:

- 대상 윤곽 또는 목적지 표시
- 행동 종류를 나타내는 커서
- 기본 행동 이름

짧은 Hover 뒤 표시:

- 거리와 자원 비용
- 명중 예상과 Advantage·Disadvantage
- 사용 불가 사유
- 이동 경로와 남은 이동력

긴 Hover 또는 상세 요청 뒤 표시:

- 규칙 설명
- 계산 근거
- 상태와 자원 상세
- 출처와 추가 조건

Tooltip은 클릭 대상을 가리지 않고 커서 진행 방향 반대쪽을 우선 사용한다.

### 5. Context Action Table

오른쪽 클릭은 선택 Actor, 대상, Session Context와 Viewer Capability를 결합해 요청 가능한 행동을 2열 버튼표로 표시한다.

권한과 가용성은 구분한다.

```text
Viewer 권한에 존재하지 않는 행동
→ 표시하지 않음

Viewer 권한에는 있으나 현재 조건을 만족하지 못한 행동
→ 비활성 색상의 버튼으로 표시
→ 클릭 불가
→ 버튼 Hover 시 커서 옆에 불가능한 이유 표시

현재 실행 가능한 행동
→ 활성 버튼으로 표시
```

버튼 옆에 항상 가능·불가능 문장을 붙이지 않는다. 불가능 사유는 비활성 버튼 Hover Tooltip에서 제공한다.

사유는 짧고 구체적으로 표현한다.

- 현재 턴이 아닙니다
- 행동을 이미 사용했습니다
- 남은 이동 거리가 부족합니다
- 대상이 사거리 밖에 있습니다
- 시야가 확보되지 않았습니다
- 필요한 자원이 없습니다
- 이 대상을 조작할 권한이 없습니다

행동 순서는 가능한 한 안정적으로 유지한다.

```text
기본 행동
→ 행동
→ 추가 행동
→ 이동
→ 상호작용
→ 정보·살펴보기
→ 허용된 DM 전용 행동
```

행동표는 규칙 원본이 아니라 Projection이다. 서버가 최종 권한·Turn·Opportunity·자원·대상 유효성을 다시 검증한다.

행동표가 열린 동안 중클릭 카메라, WASD와 Wheel 카메라 입력은 유지한다. 월드 좌클릭 기본 행동은 표가 열린 동안 실행하지 않으며 Q로 표를 닫은 뒤 복귀한다. 다른 대상을 오른쪽 클릭하면 기존 표를 새 대상의 표로 교체한다.

### 6. 행동 모드와 확인 경계

Context Action Table이나 Hotbar에서 추가 대상이 필요한 행동을 고르면 일시적인 행동 모드로 들어간다.

```text
행동 선택
→ 유효 대상과 범위 표시
→ 좌클릭으로 대상 또는 위치 지정
→ 필요 시 Preview
→ 실행 완료 후 일반 기본 행동 문맥으로 복귀
```

반복 행동은 사용자가 명시적으로 고정한 경우에만 유지하고 Q로 해제한다.

단순하고 결과가 명확한 행동은 좌클릭으로 즉시 서버 요청할 수 있다.

- 단순 이동
- 기본 단일 대상 공격
- 문 열기·닫기
- 조사와 비용 없는 기본 상호작용

다음 행동은 Preview 후 E 확인을 요구한다.

- 주문 슬롯, 희귀 소모품 또는 중요한 제한 자원 소비
- 아군 피해 가능성이 있는 광역 행동
- 여러 대상 또는 여러 변형 선택
- 집중 종료나 다른 지속 효과 종료
- 되돌리기 어려운 DM 명령
- 결과가 모호하거나 추가 판정 선택이 필요한 행동

### 7. 이동과 대상 지정 Preview

이동 위치 Hover 또는 행동 대상 지정 중 다음 정보를 가능한 범위에서 월드에 표시한다.

- 예상 경로와 총 거리
- 남은 이동력과 초과 구간
- 어려운 지형, 점프, 등반과 문 통과 구간
- 위험 지역과 기회 공격 가능 지점
- 최종 위치와 도달 불가 이유
- 사거리, 범위 형태와 영향 대상
- 엄폐, 시야와 예상 Advantage·Disadvantage

유효 대상, 불리한 유효 대상과 현재 불가능한 대상은 구분한다. 미인지 대상, 비밀 정보와 Viewer에게 공개되지 않은 Actor는 비활성 표시조차 만들지 않는다.

겹친 대상은 다음 우선순위를 기본으로 한다.

```text
현재 행동에 유효한 Actor
→ 직접 보이는 조작 가능 Actor
→ 상호작용 Object
→ 이동 표면
```

동일 위치에서 후보가 모호하면 작은 대상 선택 목록을 커서 근처에 열 수 있으며 Q로 닫는다.

### 8. Actor 선택과 턴 연속성

이동, 공격과 상호작용 완료 후 행동 주체 Actor 선택을 유지한다. 결과 대상과 Preview만 정리한다.

```text
이동
→ 공격
→ 추가 행동
→ 상호작용
→ 턴 종료
```

위 흐름에서 매 단계마다 Actor를 다시 선택하게 하지 않는다.

Party Rail, Initiative Ribbon과 월드의 조작 가능 Actor는 같은 선택 상태를 공유한다.

턴 전환은 카메라를 강제로 빼앗지 않는다.

```text
턴 시작
→ 현재 Actor를 HUD와 월드에서 강조
→ 필요 시 Frame 안내 표시
→ 사용자가 F·Space 또는 설정된 명령을 사용했을 때 카메라 이동
```

자동 초점은 사용자 설정이나 명시적 연출에서만 허용한다.

### 9. 카메라와 가림 보정

카메라는 선택과 권한을 바꾸지 않는 Projection이다.

- 마우스 휠 클릭 드래그로 Orbit
- WASD로 카메라 기준 평면 이동
- Wheel로 Zoom
- Ctrl+Wheel로 Pivot Y 이동
- 선택 Actor와 카메라 사이 구조물 투명화
- 지붕과 상층 구조의 Presentation 보정
- 카메라가 구조물 내부로 들어가지 않도록 충돌 보정

가림 보정은 Viewer의 Perception과 정보 공개를 우회하지 않는다.

### 10. 서버 요청 피드백

사용자 입력 직후 성공 결과를 가정하지 않되, 입력이 접수됐다는 피드백은 즉시 제공한다.

```text
입력 직후
→ 대상·목적지 Pending 표시

서버 승인
→ 확정 표시와 실제 실행 시작

서버 거부
→ Pending 표시 제거 또는 권위 상태로 복구
→ 커서나 관련 대상 근처에 거부 사유 표시
```

일반 행동 실패는 화면 중앙 Modal을 사용하지 않는다. 커서, 대상 또는 관련 HUD 근처에 짧은 텍스트로 표시한다.

Modal은 세션 연결 상실, 복구 불가 저장 오류, 위험한 DM 명령 확인과 반드시 응답해야 하는 Authority Prompt처럼 플레이를 계속할 수 없는 경우에 제한한다.

### 11. 턴 종료와 필수 선택

턴 종료가 불가능하면 버튼을 비활성 색상으로 표시하고 Hover 시 커서 옆에 이유를 표시한다.

- 해결 중인 행동이 있습니다
- 필수 대상 선택이 남아 있습니다
- DM 판정을 기다리고 있습니다
- 필수 반응 선택이 남아 있습니다

턴 종료가 가능하지만 사용하지 않은 이동이나 추가 행동이 있으면 버튼을 막지 않고 경고 Preview를 제공한다. E로 종료하고 Q로 돌아간다.

### 12. 정보 밀도와 접근성

정보는 사용 시점에 따라 단계적으로 노출한다.

```text
항상 표시
→ HP, 현재 행동 자원, 턴, 선택 Actor

행동 선택 시
→ 비용, 사거리, 대상 조건

Hover 시
→ 불가능 사유와 상세 규칙

확장 패널
→ 계산식, 출처와 전체 상태 목록
```

비활성 상태의 기본 시각 표현은 비활성 색상이다. 동시에 클릭을 차단하고 Hover Tooltip, 포인터 상태와 Focus 상태가 같은 `availabilityState`를 사용해야 한다.

UI Scale, Tooltip Delay, 색각 보조, 화면 흔들림 감소와 중요한 오류의 텍스트 표시를 지원한다.

### 13. Projection 일관성

World Feedback, Context Action Table, Hotbar, Party Rail, Initiative Ribbon과 End Turn UI는 같은 Projection Revision을 사용한다.

Revision 변경 시 서로 다른 UI가 공격 가능·이동 불가처럼 모순된 상태를 오래 유지하지 않도록 함께 갱신한다.

클라이언트 Preview와 Tooltip은 권위 결과가 아니다. 실행 전 서버가 최신 Snapshot으로 다시 검증한다.

## Consequences

### Positive

- 플레이어가 월드에서 직접 이동·공격·상호작용을 이어서 수행할 수 있다.
- 좌클릭 결과가 실행 전에 보이므로 기본 행동 자동 선택의 오조작이 줄어든다.
- 권한에 없는 행동과 일시적으로 불가능한 행동을 구분할 수 있다.
- Q, E와 세 포인터의 역할이 충돌하지 않는다.
- 카메라와 Actor 선택이 턴·행동마다 불필요하게 초기화되지 않는다.
- 서버 권위를 유지하면서도 입력 반응이 즉각적으로 느껴진다.

### Negative

- Hover Projection, 경로·범위 Preview와 Tooltip 배치 시스템이 필요하다.
- Context Action Table이 Capability와 가용성 변경에 따라 Revision-safe하게 갱신되어야 한다.
- 기본 행동 우선순위와 비활성 사유의 일관된 분류가 필요하다.
- 월드 피드백과 HUD Projection의 동기화 비용이 증가한다.

## Rejected Alternatives

### 오른쪽 클릭 카메라 유지

Context Action Pointer와 충돌하고 직접 플레이 행동표 접근을 방해하므로 거부한다. 카메라 Orbit은 마우스 휠 클릭 드래그로 이동한다.

### ESC를 Gameplay 취소로 사용

Q Universal Back/Cancel 계약을 이중화하고 Input Context 우선순위를 모호하게 하므로 거부한다.

### 실행 가능한 행동만 표시

현재 왜 행동을 사용할 수 없는지 학습할 수 없고 행동이 사라진 것으로 오해하게 하므로 거부한다. Viewer 권한에 존재하는 행동은 비활성 버튼과 Hover 사유로 유지한다.

### 모든 불가능 사유를 버튼 옆에 상시 표시

행동표의 정보 밀도를 과도하게 높이므로 거부한다. 비활성 색상과 Hover Tooltip을 사용한다.

### 최근 사용 행동을 자동 기본값으로 지정

같은 대상에 대한 좌클릭 결과가 예고 없이 바뀔 수 있으므로 거부한다. 기본 행동 변경은 명시적 사용자 지정만 허용한다.

### 모든 행동에 E 확인 요구

직접 플레이 흐름을 지나치게 늦추므로 거부한다. 위험·자원·다중 선택 행동에만 Preview와 E를 요구한다.

### 모든 행동 즉시 실행

광역 피해, 자원 소비와 DM 명령의 오조작 위험이 크므로 거부한다.

## Supersedes and Amends

- ADR-0039의 HUD·Capability Projection 원칙은 유지하며 Pointer·Q·가용성 표현 세부를 본 결정로 구체화한다.
- ADR-0050의 자유 전술 카메라 원칙은 유지하며 PC 기본 Orbit 바인딩을 마우스 휠 클릭 드래그로 확정한다.
- ADR-0071의 Input Context·Frozen Binding 원칙은 유지하며 `PrimaryPointer`, `ContextActionPointer`, `CameraOrbitPointer`와 Q 단계 취소를 구체화한다.
- ADR-0072의 Capability-derived Context Action Menu 원칙은 유지하며 좌클릭 기본 행동, 2열 행동표, 비활성색과 Hover 사유를 구체화한다.

## Acceptance Direction

상위 기획과 구현은 최소한 다음 증거를 제공해야 한다.

1. ESC가 Gameplay 문맥을 닫거나 취소하지 않는다.
2. Q가 행동표, 대상 지정, 반복 행동과 Actor 선택을 한 단계씩 닫는다.
3. 좌클릭 전에 기본 행동 이름과 유효성이 표시된다.
4. 오른쪽 클릭 행동표가 활성·비활성 버튼을 함께 표시한다.
5. 비활성 버튼 Hover 시 커서 옆에 구체적 사유가 표시된다.
6. 권한에 없는 행동과 미인지 대상은 노출되지 않는다.
7. 중클릭 Orbit과 우클릭 행동표가 충돌하지 않는다.
8. 이동·공격·상호작용 후 Actor 선택이 유지된다.
9. 턴 전환이 카메라를 강제 이동하지 않는다.
10. 서버 Pending·승인·거부가 서로 다른 피드백으로 표시된다.
11. 이동 경로, 비용, 위험과 대상 범위 Preview가 실행 전에 표시된다.
12. 일반 거부 사유가 관련 커서·대상 근처에 나타나고 Modal을 남용하지 않는다.
