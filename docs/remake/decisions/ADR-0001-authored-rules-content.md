# ADR-0001: 플레이어 제작 프리셋 대신 정식 규칙 콘텐츠를 직접 구현한다

- 상태: 확정
- 결정일: 2026-08-03

## 배경

기존 구상에서는 플레이어가 커스텀 마법 프리셋을 만들고, 마법의 색상·형태·범위·피해·연출 등을 직접 설정하는 범용 제작기를 제공하려 했다.

이 방식은 다른 사용자가 RVTT를 자유롭게 확장할 때는 의미가 있다. 하지만 새 RVTT는 불특정 다수를 위한 범용 플랫폼이 아니라, 개발자이자 DM이 직접 관리하는 실제 세션용 VTT를 목표로 한다.

범용 제작기를 만들면 다음 문제가 생긴다.

- 플레이어가 복잡한 설정을 직접 해야 한다.
- 어떤 마법과 특성이든 표현할 수 있는 거대한 스키마와 편집 UI가 필요하다.
- 제작기로 표현하기 어려운 예외 규칙이 생길수록 우회 설정이 늘어난다.
- 잘못된 설정, 규칙 위반, 클라이언트 조작을 검증해야 한다.
- 실제 콘텐츠 구현보다 제작 도구와 호환성 유지에 더 많은 개발 시간이 든다.
- 모든 마법이 비슷한 범용 이펙트와 버튼으로 축소되어 각 능력의 개성이 약해진다.

반면 RVTT가 사용할 규칙 콘텐츠를 개발자가 직접 추가한다면, 각 능력에 필요한 전용 입력·판정·연출을 만들 수 있다.

## 결정

RVTT는 플레이어가 마법과 특성을 조립하는 범용 제작기를 핵심 기능으로 제공하지 않는다.

지원하는 마법, 클래스 특성, 종족 특성, 몬스터 능력, 아이템 행동은 RVTT의 정식 콘텐츠로 직접 구현한다.

각 콘텐츠는 고유한 `ContentId`를 가지며, 캐릭터와 액터 데이터는 전체 규칙을 복사해서 저장하지 않고 해당 콘텐츠를 참조한다.

예시:

```text
Spell.Fireball
Spell.Sleep
Feature.Barbarian.Rage
Feature.Rogue.SneakAttack
Feature.Paladin.DivineSmite
Monster.Goblin.NimbleEscape
Item.Weapon.Longsword.Attack
```

## 구현 구조

### 1. 콘텐츠 정의

모든 콘텐츠는 검색, 캐릭터 시트, 툴팁, 규칙 확인에 필요한 정적 정보를 가진다.

- 이름과 분류
- 사용 가능한 액터 조건
- 행동 종류
- 사거리와 기본 대상 방식
- 자원과 재사용 조건
- 지속시간과 집중 여부
- 규칙 태그
- 실행 모듈과 연출 프로필 참조

### 2. 공통 규칙 프리미티브

반복되는 규칙은 공통 서비스로 제공한다.

- 대상 지정
- 거리와 시야 검사
- 공격 굴림
- 내성 굴림
- 피해와 회복
- 상태 적용과 제거
- 지속시간과 턴 이벤트
- 집중
- 자원 소비와 회복
- 강제 이동과 순간이동
- 범위 템플릿
- 소환과 임시 오브젝트
- 반응 조건과 사용 시점
- 선택지와 DM 승인

### 3. 콘텐츠별 실행 모듈

각 마법과 특성은 필요한 공통 프리미티브를 조합하는 전용 실행 모듈을 가진다.

단순한 능력은 선언적인 단계 목록으로 구현할 수 있다. 복잡하거나 독특한 능력은 전용 Luau 로직을 작성한다.

따라서 시스템은 다음 두 극단을 모두 피한다.

- 모든 마법을 서로 무관한 거대한 개별 스크립트로 복사 구현
- 모든 마법을 하나의 제한적인 범용 설정 스키마에 억지로 끼워 넣기

### 4. 콘텐츠별 표현

규칙 처리와 시청각 표현은 분리하되, 각 콘텐츠가 자기 연출을 명시할 수 있게 한다.

- 시전 애니메이션
- 투사체 또는 범위 VFX
- 명중과 실패 연출
- 상태 표시
- SFX
- 카메라 피드백
- 전투 로그 문장

색상만 바꾼 공통 마법 효과가 아니라, 중요한 마법과 특성은 고유한 사용 감각을 가질 수 있다.

### 5. 예외와 자유도

모든 능력을 무조건 완전 자동화하지는 않는다. 창의적 해석이나 DM 판단이 필요한 능력도 다음과 같은 전용 흐름을 제공한다.

- 플레이어의 의도 입력
- 대상·지점·오브젝트 선택
- 선택지와 추가 설명
- 임시 토큰·영역·메모 생성
- 지속시간과 집중 추적
- DM 승인, 수정, 기각
- 필요한 판정 실행

즉, 결과를 시스템이 전부 결정하지 못하더라도 해당 능력 자체는 RVTT 안에 실제 기능으로 존재한다.

## 구현 수준

각 콘텐츠는 다음 중 하나로 분류한다.

### 완전 실행형

시스템이 사용 조건 확인부터 결과 적용까지 처리한다.

예시:

- 정해진 피해를 주는 단일 대상 공격
- 범위 내 대상의 내성 굴림과 피해 적용
- 정해진 상태 부여
- 치유와 자원 회복

### 유도 실행형

시스템이 실행 절차와 상태를 관리하지만 플레이어나 DM의 선택이 필요하다.

예시:

- 여러 효과 중 하나를 선택하는 마법
- 명중 후 사용할지 결정하는 강타
- 조건 충족 여부를 확인하는 암습
- 소환할 형태를 선택하는 능력

### 판정 보조형

효과의 의미가 상황에 크게 의존한다. 시스템은 전용 도구와 추적 기능을 제공하고 최종 결과는 DM이 확정한다.

예시:

- 환상으로 무엇을 만들지 정하는 능력
- 자유로운 명령문을 사용하는 능력
- 환경이나 서사에 직접 영향을 주는 능력

## 구체적 예시

### 화염구

1. 플레이어가 행동 목록에서 화염구를 선택한다.
2. 시스템이 주문 슬롯과 시전 가능 상태를 확인한다.
3. 플레이어가 유효 사거리 안의 지점을 지정한다.
4. 반경 범위와 영향받는 대상이 표시된다.
5. 각 대상이 민첩 내성 굴림을 한다.
6. 주문 레벨에 맞는 피해를 굴리고 성공 여부에 따라 적용한다.
7. 주문 슬롯을 소비한다.
8. 전용 VFX, SFX, 로그를 출력한다.

### 야만인의 격노

1. 보너스 행동으로 격노를 시작한다.
2. 남은 사용 횟수를 소비한다.
3. 관련 피해 보너스와 저항을 활성화한다.
4. 토큰과 UI에 격노 상태를 표시한다.
5. 턴 진행에 따라 종료 조건을 검사한다.
6. 플레이어 또는 DM이 강제로 종료할 수 있다.

### 암습

1. 공격이 명중했을 때 암습 가능 조건을 검사한다.
2. 이번 턴 사용 여부, 무기 조건, 이점·불리점, 인접 아군 등을 확인한다.
3. 사용 가능하면 플레이어에게 적용 여부를 묻는다.
4. 선택하면 추가 피해를 적용하고 이번 턴 사용됨으로 기록한다.
5. 조건이 모호하면 DM이 허용 또는 거부할 수 있다.

### 하급 환영

1. 플레이어가 소리 또는 형상을 선택한다.
2. 형상이라면 위치와 크기를 지정하고 간단한 설명을 입력한다.
3. RVTT가 임시 환영 오브젝트와 지속시간을 생성한다.
4. 플레이어별 가시성과 조사 판정을 관리한다.
5. 환영의 구체적인 반응과 설득력은 DM이 판정한다.

## 홈브루 처리

홈브루 콘텐츠가 필요할 경우 플레이어가 런타임에서 범용 제작기로 만드는 대신 개발자가 새 콘텐츠 모듈을 저장소에 추가한다.

반복적인 홈브루 추가가 많아진 뒤에만 개발자용 템플릿, 코드 생성기, 내부 편집 도구를 검토한다. 이 도구가 생기더라도 플레이어용 범용 마법 제작기와는 구분한다.

## 결과

### 장점

- 플레이어가 설정하지 않아도 마법과 특성을 바로 사용할 수 있다.
- 각 능력의 독특한 규칙과 연출을 정확하게 표현할 수 있다.
- UI가 능력에 맞게 단순해진다.
- 서버가 모든 실행과 상태를 검증하기 쉽다.
- 범용 제작기의 한계 때문에 규칙을 왜곡할 필요가 없다.
- 실제 세션에서 텍스트를 읽고 수동 처리하는 시간이 크게 줄어든다.

### 비용

- 지원하는 콘텐츠를 개발자가 하나씩 추가하고 테스트해야 한다.
- 콘텐츠 수가 많아질수록 회귀 테스트와 버전 관리가 중요해진다.
- 공통 프리미티브의 설계가 잘못되면 콘텐츠 구현마다 예외 코드가 늘어난다.
- 규칙 출처와 배포 범위를 별도로 정해야 한다.
- 최초 MVP에서 모든 콘텐츠를 동시에 구현할 수 없으므로 우선순위가 필요하다.

## 후속 결정

다음 사항은 별도 문서에서 결정한다.

1. 기준으로 삼을 D&D 버전과 규칙 출처
2. 첫 MVP에서 지원할 클래스, 레벨, 마법, 몬스터 범위
3. 콘텐츠 레지스트리와 실행 모듈의 정확한 인터페이스
4. 공통 효과 프리미티브 목록
5. 캐릭터 생성과 콘텐츠 부여 방식
6. 콘텐츠별 테스트 규격
7. 전용 VFX를 어느 수준까지 초기 범위에 포함할지
