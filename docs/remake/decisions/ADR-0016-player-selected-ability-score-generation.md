# ADR-0016: 플레이어 선택형 능력치 생성 방식

- 상태: 확정
- 결정일: 2026-08-03
- 관련 문서:
  - [`ADR-0002`](ADR-0002-integrated-character-progression.md)
  - [`ADR-0015`](ADR-0015-character-identity-profile-and-default-presentation.md)

## 배경

캐릭터 생성에서 능력치 생성 방식을 캠페인 설정으로 제한하면, 플레이어가 자신의 캐릭터에 맞는 생성 방식을 고를 자유가 줄어든다.

다만 모든 생성 방식을 처음부터 같은 비중으로 제시하면 초보 플레이어가 무엇을 선택해야 하는지 알기 어렵고, 가장 일반적이고 검증하기 쉬운 흐름으로 바로 시작하기 어렵다.

RVTT의 기본 방향은 표준 배열을 기본 선택값으로 제공하되, 플레이어가 원하면 다른 지원 방식을 직접 선택할 수 있게 하는 것이다.

## 결정

능력치 생성 방식은 캠페인별 허용 목록으로 켜고 끄지 않는다.

캐릭터 생성 화면에 처음 진입하면 **표준 배열**이 기본 선택되어 있다.

플레이어는 기본 선택을 그대로 사용하거나, RVTT가 지원하는 다른 생성 방식으로 변경할 수 있다.

```text
Character Creation
└─ Ability Score Method Selection
   ├─ 기본 선택: 표준 배열
   ├─ 선택 가능한 다른 방식 표시
   ├─ 플레이어가 필요하면 방식 변경
   ├─ 선택한 방식의 절차 진행
   ├─ 시스템이 결과 검증
   └─ 생성 방식과 근거를 progression에 저장
```

캠페인 설정은 기본적으로 특정 생성 방식을 금지하거나 강제하지 않는다.

표준 배열이 기본값이라는 것은 다른 방식을 숨기거나 불리하게 만드는 뜻이 아니다. 별도의 DM 승인 없이 플레이어가 생성 과정 안에서 직접 변경할 수 있어야 한다.

## 최초 지원 방향

기본 캐릭터 생성 흐름은 다음 방식을 지원하는 방향으로 설계한다.

- `standard_array`: 기본 선택값
- `point_buy`: 플레이어가 선택 가능한 대체 방식
- `dice_roll`: 플레이어가 선택 가능한 대체 방식

직접 수치 입력 방식은 공식 생성 방식과 검증 흐름을 우회할 가능성이 있으므로 이 결정에 포함하지 않는다. 필요하면 DM 관리 기능 또는 별도 가져오기 정책에서 다룬다.

각 방식의 정확한 수치, 비용표, 굴림식과 재굴림 규칙은 해당 규칙 세트의 콘텐츠 정의와 후속 구현명세에서 확정한다.

## UI 원칙

- 캐릭터 생성 화면은 표준 배열 배정 단계로 바로 시작할 수 있어야 한다.
- 현재 사용 중인 생성 방식은 항상 명확하게 표시한다.
- `방식 변경`을 선택하면 지원되는 다른 방식을 비교하고 선택할 수 있다.
- 방식을 변경하기 전에 기존 배정이나 굴림 결과가 사라질 수 있음을 알린다.
- 변경을 확정하면 이전 방식의 임시 결과를 폐기하고 새 방식의 초안을 생성한다.
- 최종 캐릭터를 확정하기 전까지는 생성 방식을 다시 변경할 수 있다.

## 저장 원칙

캐릭터 성장 원본에는 최종 능력치만 저장하지 않는다.

최소한 다음을 함께 기록한다.

- 선택한 생성 방식 ID
- 생성 방식의 버전 또는 규칙 세트
- 생성 과정에서 나온 원본 값
- 각 원본 값이 어느 능력치에 배정되었는지
- 배경, 특성, 재주와 레벨업으로 추가된 영구 보정
- 서버 검증에 필요한 생성 기록

개념 예시:

```text
abilityScores
├─ generationMethodId
├─ generationMethodVersion
├─ generatedValues
├─ assignments
├─ permanentAdjustments
└─ finalBaseScores
```

`finalBaseScores`는 편의를 위해 저장할 수 있지만, 생성 기록과 영구 보정에서 다시 계산하고 검증할 수 있어야 한다.

표준 배열을 사용한 경우에는 어떤 배열 값을 어느 능력치에 배정했는지 저장한다.

포인트 구매를 사용한 경우에는 시작값, 능력치별 구매 결과, 사용한 총 포인트와 비용표 버전을 저장한다.

주사위 굴림을 사용한 경우에는 서버가 확정한 굴림 결과, 배정 결과와 굴림 규칙 버전을 저장한다.

## 일시적 변경과의 분리

다음 효과는 성장 원본에 기록하지 않는다.

- 장비로 인한 능력치 변경
- 주문과 상태 효과
- 일시적 버프와 디버프
- 특정 씬이나 전투에서만 적용되는 보정

이 값들은 파생 능력치 계산 단계에서 적용한다.

## 검증

서버는 캐릭터 확정 시 다음을 검증한다.

- 지원되는 생성 방식인지
- 방식별 규칙에 맞게 값이 생성되었는지
- 같은 생성 값을 중복 배정하지 않았는지
- 허용 범위를 벗어난 값이 없는지
- 포인트 구매 비용이 정확한지
- 주사위 굴림 기록이 서버가 확정한 결과인지
- 영구 보정의 출처와 선택 조건이 유효한지
- 최종 기본 능력치가 생성 기록과 일치하는지

클라이언트가 보낸 최종 능력치만 신뢰하지 않는다.

## 생성 완료 후 변경

캐릭터 생성이 최종 확정되기 전에는 생성 방식을 변경할 수 있다.

캐릭터 생성이 확정된 뒤에는 일반 편집으로 생성 방식을 바꾸거나 능력치를 다시 생성하지 않는다. 재생성이 필요하면 별도의 DM 관리 또는 캐릭터 재구성 기능에서 원자적으로 처리한다.

## 아직 확정하지 않는 사항

다음은 후속 기획과 구현명세에서 정한다.

- 표준 배열의 정확한 값과 규칙 세트별 차이
- 포인트 구매의 정확한 비용표와 UI
- 주사위 굴림의 정확한 굴림식
- 주사위 재굴림과 전체 초기화 정책
- 생성 방식 비교 화면의 구체적인 레이아웃
- DM 관리형 능력치 재구성 정책

## 결과

- 처음 접한 플레이어는 표준 배열로 즉시 캐릭터 생성을 시작할 수 있다.
- 원하는 플레이어는 포인트 구매나 주사위 굴림을 직접 선택할 수 있다.
- 캠페인 설정이 캐릭터 생성 방식을 불필요하게 통제하지 않는다.
- 최종 능력치의 생성 근거를 추적하고 재검증할 수 있다.
- 이후 새로운 생성 방식을 추가해도 캐릭터 성장 데이터의 공통 구조를 유지할 수 있다.
