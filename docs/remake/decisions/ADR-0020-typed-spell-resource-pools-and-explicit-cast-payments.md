## 배경

주문은 여러 종류의 비용으로 시전될 수 있다.

- 일반 주문 슬롯
- 다중직업에서 공유하는 주문 슬롯
- 워락형 별도 슬롯
- 종·재주·특성이 제공하는 무료 시전
- 아이템 충전
- 직업 자원이나 특수 포인트
- 슬롯을 쓰지 않는 의식 시전
- 소모되는 물질 구성요소와 금전 가치가 있는 재료

이 비용을 모두 하나의 `spellPoints` 또는 일반 주문 슬롯으로 변환하면 다음 문제가 생긴다.

- 회복 시점과 슬롯 레벨 규칙이 다른 자원이 섞인다.
- 무료 시전이 일반 슬롯처럼 다른 주문에 사용될 수 있다.
- 아이템을 잃어도 캐릭터에게 충전 수치가 남는다.
- 워락형 슬롯과 일반 슬롯의 시전 레벨 차이가 사라진다.
- 의식 시전이 가짜 0레벨 슬롯처럼 취급된다.
- 같은 주문을 여러 출처로 얻었을 때 어떤 자원을 소비했는지 추적할 수 없다.

## 결정

RVTT는 주문 관련 자원을 **타입이 있는 독립 자원 풀**로 유지한다.

```text
ResourcePool
├─ RankedSpellSlotPool
├─ FixedRankSpellSlotPool
├─ LimitedCastAllowance
├─ FeaturePointPool
├─ ItemChargePool
└─ TemporaryCastPool
```

모든 자원을 같은 저장 형태로 강제하지 않는다. 각 자원 풀은 자신의 등급 구조, 최대값 계산, 현재 상태, 소유 범위와 회복 정책을 가진다.

`SpellCastRoute`는 현재 사용할 수 있는 하나 이상의 `CastPaymentOption`을 생성한다.

```text
SpellCastRoute
└─ CastPaymentOption[]
   ├─ 일반 3레벨 슬롯 사용
   ├─ 워락형 5레벨 슬롯 사용
   ├─ 재주 무료 시전 1회 사용
   └─ 지팡이 충전 3점 사용
```

한 번의 시전에서는 정확히 하나의 주 결제 선택지를 선택한다. 물질 구성요소처럼 추가로 필요한 비용은 선택된 주 결제와 함께 하나의 `CastCostPlan`에 포함한다.

## 자원 풀 구분

### 등급별 일반 주문 슬롯

레벨별 최대량과 소모량을 가진다. 다중직업 규칙으로 생성되는 공유 슬롯은 캐릭터 범위의 하나의 풀로 구성할 수 있으며, 여러 `SpellcastingProfile`이 규칙상 허용될 때 같은 풀을 참조한다.

### 고정 등급 별도 슬롯

워락형 슬롯처럼 모든 현재 슬롯이 하나의 유효 시전 레벨을 공유하고 별도의 개수와 회복 규칙을 가지는 풀이다. 일반 슬롯 풀에 합치지 않는다.

### 제한된 무료 시전

특정 주문 또는 제한된 주문 집합에만 사용할 수 있는 사용권이다. 가짜 주문 슬롯으로 만들지 않는다.

무료 시전의 시전 레벨, 사용 횟수, 회복 조건과 슬롯을 사용한 추가 시전 허용 여부는 해당 Grant 또는 `SpellcastingProfile`이 정의한다.

### 아이템 충전

아이템 충전은 연결된 `ItemInstance`가 소유한다. 캐릭터의 일반 자원 상태에 복사하지 않는다. 아이템 접근, 장착, 조율과 사용 조건이 사라지면 해당 결제 선택지도 비활성화된다.

### 의식 시전

의식 시전은 자원 풀이 아니다. 주문 슬롯 대신 추가 시간과 의식 적격성을 요구하는 별도 시전 경로 또는 결제 옵션이다.

## 시전 레벨

주문의 실제 `castLevel`은 주문 정의나 캐릭터에 고정 저장하지 않고 선택된 결제 옵션에서 결정한다.

- 일반 슬롯은 선택한 슬롯 등급을 사용한다.
- 고정 등급 별도 슬롯은 현재 풀의 유효 등급을 사용한다.
- 무료 시전은 Grant가 정한 고정 또는 계산 등급을 사용한다.
- 아이템은 아이템 정의가 정한 시전 등급을 사용한다.
- 캔트립은 주문 슬롯 등급과 별도의 성장 규칙을 사용한다.

주문 효과 엔진은 자원의 이름이 아니라 확정된 `castLevel`과 시전자 규칙 문맥을 받는다.

## 결제 트랜잭션

시전 비용은 다음 단계로 처리한다.

```text
시전 경로와 결제 옵션 선택
→ 대상과 입력 수집
→ 서버 적격성 검증
→ 행동 경제·자원·소모품 예약
→ 규칙상 결제 확정 시점 도달
→ 예약 자원 원자적 확정
→ 주문 해결
```

확정 이전에 입력이 취소되거나 검증이 실패하면 예약을 되돌린다.

확정 이후 주문이 상쇄되거나 효과가 실패했을 때 비용을 돌려주는지는 해당 규칙이 결정한다. 결제 엔진이 모든 실패를 자동 환불하지 않는다.

## 저장 원칙

저장한다.

- 각 영구 자원 풀의 현재 소모 상태
- 아이템 인스턴스의 현재 충전
- 무료 시전과 특성 자원의 현재 사용 상태
- 회복 또는 재충전에 필요한 영구 상태

파생한다.

- 자원 풀의 최대량
- 다중직업 공유 슬롯 표
- 워락형 슬롯의 현재 유효 등급
- 현재 주문에 사용할 수 있는 결제 선택지
- 선택한 결제에 따른 `castLevel`
- UI의 추천 결제 옵션

현재 소모 상태는 ADR-0011에 따라 세션 종료와 재접속 뒤에도 유지되며 현실 시간만으로 자동 회복되지 않는다.

## 결과

- 서로 다른 주문 자원의 규칙과 회복 시점을 정확히 유지할 수 있다.
- 한 주문을 일반 슬롯, 별도 슬롯, 무료 시전과 아이템으로 사용하는 경우를 모두 표현할 수 있다.
- 다중직업 프로필은 준비 규칙을 분리하면서 공유 슬롯 풀을 사용할 수 있다.
- 무료 시전과 아이템 충전이 다른 주문에 잘못 사용되는 것을 막을 수 있다.
- 결제 UI와 서버 검증이 복잡해지므로 결제 선택과 비활성 이유를 명확하게 표시해야 한다.
