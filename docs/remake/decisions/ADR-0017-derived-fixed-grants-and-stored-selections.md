# ADR-0017: 고정 획득은 파생하고 선택과 예외 획득만 저장한다

- 상태: 확정
- 결정일: 2026-08-03
- 관련 문서:
  - [`ADR-0002`](ADR-0002-integrated-character-progression.md)
  - [`ADR-0003`](ADR-0003-ruleset-source-packs-localization.md)
  - [`10. Grant Graph와 Capability 모델`](../10-rules-content-grant-capability-model.md)

## 배경

캐릭터는 종, 배경, 직업 레벨, 하위직업, 재주와 장비를 통해 많은 특성, 주문 권한, 숙련과 규칙 변경을 얻는다.

직업 레벨만 보면 항상 결정되는 고정 특성까지 캐릭터 저장 데이터에 다시 나열하면 다음 문제가 생긴다.

- 직업 레벨과 저장된 특성 목록이 서로 어긋날 수 있다.
- 레벨 취소, 재구성 또는 다중직업 변경 시 중복과 누락을 정리해야 한다.
- 규칙 콘텐츠가 정오표나 마이그레이션으로 바뀔 때 모든 캐릭터의 중복 목록을 수정해야 한다.
- 특성 정의와 실행 로직이 캐릭터 데이터에 복사될 위험이 커진다.
- 시트, 행동 UI와 전투 시스템이 서로 다른 목록을 원본으로 사용할 수 있다.

반대로 전투 방식, 웨폰 마스터리 대상, 습득 주문처럼 플레이어가 실제로 선택한 결과는 직업 레벨만으로 다시 만들 수 없다. DM이 서사 보상이나 예외로 부여한 콘텐츠도 명시적인 기록이 필요하다.

## 결정

캐릭터 저장 원본에는 **성장 출처, 선택 결과와 예외 획득**을 저장한다.

직업 레벨과 콘텐츠 정의만으로 결정적으로 재구성할 수 있는 고정 획득은 별도 목록으로 저장하지 않고 `Grant Graph`에서 파생한다.

```text
캐릭터 성장 원본
+ 고정된 ruleset과 출처 팩 버전
+ RulesContentCatalog
+ 저장된 선택 결과와 예외 획득
→ ResolvedGrant
→ Character Capability Set
```

## 저장하는 데이터

### 성장 출처

- 종과 세부 선택
- 배경
- 직업별 레벨과 레벨 획득 순서
- 하위직업
- 직접 선택한 재주
- 장비와 조율 상태처럼 현재 활성 출처를 결정하는 원본

### 선택 결과

- 전투 방식
- 웨폰 마스터리 대상 무기
- 선택형 숙련과 언어
- 습득, 준비 또는 교체한 주문
- 재주가 제공한 하위 선택
- 레벨업에서 선택한 능력치 향상과 기타 선택
- 같은 선택 정의가 여러 번 발생했을 때의 `sourceOccurrenceId`

### 예외 획득

- DM이 직접 부여한 특성, 재주, 주문 권한 또는 숙련
- 서사 사건과 보상으로 얻은 능력
- 데이터 복구 또는 승인된 홈브루 획득
- 부여 이유, 출처 이벤트, 부여자와 콘텐츠 버전

## 저장하지 않는 데이터

다음 값은 권위 원본으로 저장하지 않는다.

- 직업 레벨에서 자동으로 얻는 고정 특성 목록
- 종과 하위직업 정의에서 자동으로 얻는 고정 특성 목록
- 최종 `ResolvedGrant` 목록
- 최종 `Character Capability Set`
- 현재 행동 버튼 목록
- 추가 공격 횟수, 최대 자원과 같은 파생 결과
- 장착 장비에서 현재 활성화된 Capability 사본
- 특성, 재주와 주문의 전체 규칙 정의
- 번역된 이름과 설명

성능을 위해 캐시할 수 있지만, 캐시는 원본 revision과 콘텐츠 버전이 맞지 않으면 폐기하고 다시 만든다.

## 버전과 마이그레이션

고정 획득을 파생하려면 어떤 규칙 정의를 사용했는지 결정적이어야 한다.

캐릭터와 캠페인은 다음을 추적한다.

- `rulesetId`
- 활성 출처 팩 ID와 버전
- 저장된 선택이 참조한 콘텐츠와 선택 정의 버전
- 캐릭터 성장 원본 revision

출처 팩 업데이트가 고정 획득을 변경하는 경우에는 다음 중 하나를 명시적인 마이그레이션 정책으로 선택한다.

- 기존 캠페인이 이전 콘텐츠 버전을 유지
- 새 버전으로 원자적으로 마이그레이션
- 호환되지 않는 선택을 검토 대상으로 표시

새 정의를 조용히 적용해 캐릭터 기능을 예고 없이 변경하지 않는다.

## 누락 또는 손상된 콘텐츠

출처 팩이나 콘텐츠 정의가 누락되어도 저장된 성장 출처와 선택 기록을 삭제하지 않는다.

- 재구성하지 못한 Grant를 `unresolved` 상태로 표시한다.
- 해당 Capability를 정상 작동하는 것처럼 노출하지 않는다.
- 캐릭터 시트에서 누락 원인과 복구 대상을 보여준다.
- 원본 기록을 보존한 채 팩 복구 또는 마이그레이션을 기다린다.

## 검증

서버는 캐릭터 로드, 생성 확정과 레벨업 확정 시 다음을 검사한다.

- 성장 출처와 레벨 순서가 유효한가
- 저장된 선택이 해당 `sourceOccurrenceId`에서 실제로 요구되는가
- 선택한 콘텐츠가 당시 후보군과 조건을 만족하는가
- 선택 개수, 중복과 배타 규칙이 맞는가
- 예외 획득이 유효한 콘텐츠와 출처를 참조하는가
- 현재 규칙 버전으로 Grant Graph를 순환 없이 재구성할 수 있는가
- 최종 Capability Set이 서버에서 결정적으로 계산되는가

클라이언트가 보낸 고정 특성 목록, Capability 목록과 파생 수치를 신뢰하지 않는다.

## 결과

- 캐릭터 저장 원본이 작고 명확해진다.
- 레벨과 고정 특성 목록의 불일치를 구조적으로 막는다.
- 직업과 출처 팩 업데이트를 마이그레이션 가능한 단위로 관리할 수 있다.
- 플레이어의 실제 선택과 DM 예외는 정확히 보존된다.
- 시트, 행동 UI와 전투 시스템이 같은 파생 Capability Set을 사용한다.

## 비목표

- 모든 캐릭터를 항상 최신 규칙으로 자동 변경하지 않는다.
- 캐시 사용을 금지하지 않는다.
- 선택 기록 없이 최종 능력치와 행동 목록만 저장하지 않는다.
- 누락된 콘텐츠 기록을 자동 삭제하거나 다른 콘텐츠로 임의 교체하지 않는다.
