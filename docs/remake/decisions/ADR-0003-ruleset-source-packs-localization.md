# ADR-0003: D&D 2024 기준 규칙, 공식 출처 팩, 한국어 우선 다국어 구조

- 상태: 확정
- 결정일: 2026-08-03
- 관련 결정:
  - ADR-0001 정식 규칙 콘텐츠 직접 구현
  - ADR-0002 통합 캐릭터 시트와 레벨 진행 시스템

## 배경

새 RVTT는 캐릭터 생성, 시트, 레벨업, 직업, 하위직업, 주문, 장비와 전투 기능을 하나의 규칙 시스템으로 통합한다.

이 시스템을 구현하려면 다음 세 가지를 초기에 확정해야 한다.

1. 어떤 D&D 규칙판을 기준으로 삼을 것인가
2. 이후 공식 서적의 콘텐츠를 어떻게 추가할 것인가
3. 한국어를 기본으로 사용하면서 다른 언어를 어떻게 지원할 것인가

규칙판과 출처가 섞이거나, 이름과 설명이 코드에 직접 박히면 콘텐츠가 늘어날수록 캐릭터 데이터와 전투 로직을 유지하기 어려워진다.

## 결정

### 1. 기본 규칙판

RVTT의 기본 규칙판은 **D&D 2024 개정 규칙**으로 한다.

내부 규칙 세트 식별자는 다음과 같이 고정한다.

```text
dnd5e-2024
```

직업 진행, 하위직업 획득 레벨, 주문 규칙, 무기 숙련, 행동 규칙, 상태와 캐릭터 생성 절차는 이 규칙 세트를 기준으로 구현한다.

2014 규칙을 기본 규칙에 혼합하지 않는다. 나중에 2014 규칙을 지원할 필요가 생기면 별도의 규칙 세트로 취급한다.

```text
dnd5e-2014
```

한 캐릭터와 캠페인은 하나의 기본 규칙 세트를 가진다.

### 2. 공식 서적은 출처 팩으로 추가

추가 공식 서적의 콘텐츠는 코어 시스템을 직접 수정하는 방식이 아니라 **출처 팩(Source Pack)** 단위로 추가한다.

출처 팩은 개발자가 저장소와 Roblox Studio를 통해 등록하는 내부 콘텐츠 패키지다. 플레이어가 임의로 만드는 플러그인 시스템은 아니다.

출처 팩은 필요에 따라 다음을 포함할 수 있다.

- 직업
- 하위직업
- 종 또는 종족
- 배경
- 재주
- 주문
- 장비
- 마법 아이템
- 몬스터
- 몬스터 행동과 전설 행동
- 상태와 효과
- 선택형 규칙
- 규칙 수정 또는 기존 콘텐츠 확장
- VFX, SFX, 애니메이션과 아이콘
- 각 언어의 이름과 설명

각 팩은 최소한 다음 정보를 가진다.

```text
packId
version
rulesetId
sourceId
dependencies
loadOrder
contentIndex
locales
```

예시 구조:

```text
Content/
├─ Rulesets/
│  └─ dnd5e-2024/
│     ├─ EngineRules/
│     ├─ CoreDefinitions/
│     └─ Validation/
├─ SourcePacks/
│  ├─ core-2024/
│  │  ├─ manifest.lua
│  │  ├─ Classes/
│  │  ├─ Features/
│  │  ├─ Spells/
│  │  ├─ Items/
│  │  ├─ Monsters/
│  │  └─ Locales/
│  └─ future-source-pack/
└─ Localization/
   └─ Shared/
```

실제 폴더명은 기술 설계에서 조정할 수 있지만 규칙 세트, 출처 팩, 번역 리소스의 분리는 유지한다.

### 3. 캠페인별 활성 출처 관리

각 캠페인은 다음 정보를 저장한다.

```text
rulesetId = "dnd5e-2024"
enabledSourcePacks = {
    { packId = "core-2024", version = "..." },
    { packId = "...", version = "..." },
}
```

캐릭터 생성과 레벨업 화면에는 해당 캠페인에서 활성화한 출처의 콘텐츠만 나타난다.

DM은 캠페인을 만든 뒤 출처 팩을 추가할 수 있다. 출처 팩을 제거하려 할 때 해당 팩의 직업, 특성, 주문 또는 아이템을 사용하는 캐릭터가 있다면 시스템이 경고하고 제거를 막거나 명시적인 마이그레이션을 요구한다.

### 4. 콘텐츠의 고정 식별자

콘텐츠는 표시 이름으로 참조하지 않는다.

잘못된 예:

```text
character.spells["화염구"]
```

올바른 예:

```text
character.spells["spell.fireball"]
```

각 콘텐츠는 언어와 무관한 고정 ID를 가진다.

```text
class.fighter
subclass.fighter.champion
feature.fighter.action_surge
spell.fireball
condition.prone
item.weapon.longbow
```

캐릭터 저장 데이터, 전투 로그의 구조화 데이터, 효과 출처, 규칙 의존성은 이 ID를 사용한다.

번역된 이름과 설명은 저장하지 않는다. 화면에 표시할 때 현재 언어의 번역 리소스에서 가져온다.

### 5. 기본 언어와 로케일

RVTT의 기본 표시 언어는 한국어다.

```text
defaultLocale = "ko-KR"
```

초기 공개 범위에서는 한국어 번역의 완성도를 가장 우선한다.

다만 시스템 전체는 처음부터 다국어를 전제로 만든다.

- 코드에 한국어 UI 문구를 직접 작성하지 않는다.
- 콘텐츠 데이터에 한국어 이름을 유일한 식별자로 저장하지 않는다.
- 이미지에 메뉴명과 설명을 직접 새겨 넣지 않는다.
- 버튼 크기와 레이아웃은 다른 언어의 길이 변화를 견딜 수 있어야 한다.
- 문장 조립이 필요한 로그는 번역 템플릿과 변수로 구성한다.
- 숫자, 단위, 조사, 복수형 등은 로케일별 포매터가 처리한다.

예시:

```text
localizationKey = "spell.fireball.name"
descriptionKey = "spell.fireball.description"
```

한국어 리소스:

```text
spell.fireball.name = "화염구"
```

다른 언어를 추가할 때 실행 로직과 캐릭터 데이터는 수정하지 않고 번역 리소스만 추가한다.

### 6. 번역 누락 처리

번역 키를 찾지 못했을 때 빈 문자열이나 내부 ID만 표시하지 않는다.

우선순위는 다음과 같다.

1. 사용자가 선택한 로케일
2. 해당 콘텐츠 팩이 지정한 보조 로케일
3. 시스템 공통 fallback 로케일
4. 개발용 누락 표시

초기에는 한국어를 완성된 기본 언어로 제공한다. 영어 fallback의 실제 제공 범위는 별도로 정하지만, 시스템이 fallback 로케일을 지원하도록 만든다.

개발 환경에서는 누락된 키가 즉시 드러나도록 표시하고 로그에 기록한다.

### 7. 규칙 로직과 번역의 분리

다음 요소는 번역 파일에 넣지 않는다.

- 피해 주사위
- 행동 비용
- 사거리
- 대상 규칙
- 레벨 요구사항
- 획득 조건
- 자원 소비
- 효과 실행 순서
- 내성 굴림 종류
- 지속시간

다음 요소는 번역 리소스로 분리한다.

- 이름
- 짧은 이름
- 설명
- 선택지 문구
- 오류와 경고
- 전투 로그 문장
- 툴팁
- 튜토리얼

번역이 바뀌어도 규칙 결과가 바뀌어서는 안 된다.

### 8. 출처와 버전 추적

모든 콘텐츠 정의는 자신의 출처 팩과 버전을 추적할 수 있어야 한다.

캐릭터의 영구 선택에는 최소한 콘텐츠 ID와 선택 당시의 출처 정보를 연결한다.

이를 통해 다음을 처리한다.

- 공식 정오표 또는 업데이트
- 콘텐츠 팩 버전 변경
- 동일 이름의 다른 규칙판 콘텐츠 구분
- 캠페인 로드 시 누락된 팩 탐지
- 오래된 캐릭터 데이터 마이그레이션

콘텐츠 업데이트가 기존 캐릭터의 능력을 자동으로 바꾸는지, 이전 버전을 유지하는지는 업데이트 유형에 따라 명시적으로 결정한다.

### 9. 충돌과 덮어쓰기

출처 팩은 다른 팩의 콘텐츠를 이름만 같다는 이유로 덮어쓰지 못한다.

동일 콘텐츠를 수정해야 할 경우 manifest에 명시적인 대상 ID와 패치 관계를 선언한다.

```text
patches = {
    "spell.example",
}
```

로드 순서와 충돌 결과는 결정적이어야 한다. 충돌이 해결되지 않으면 서버 시작 또는 캠페인 로드 단계에서 오류로 처리한다.

### 10. 배포 범위

출처 팩 구조는 공식 서적을 나중에 추가할 수 있도록 설계한다. 다만 저장소와 게임에 포함하거나 배포하는 실제 텍스트, 이미지, 음원과 기타 자료는 사용 가능한 권리와 배포 범위를 확인한 콘텐츠로 제한한다.

규칙 실행 구조와 콘텐츠 팩 인터페이스는 공개 코드와 분리할 수 있어야 하며, 필요한 경우 특정 출처 팩을 비공개 또는 별도 배포 단위로 관리할 수 있어야 한다.

## 결과

### 장점

- D&D 2024 규칙에 맞춘 일관된 캐릭터와 전투 시스템을 만들 수 있다.
- 새 공식 서적을 코어 엔진을 뒤엎지 않고 추가할 수 있다.
- 캠페인마다 허용할 출처를 통제할 수 있다.
- 한국어를 기본으로 완성하면서도 나중에 다른 언어를 추가할 수 있다.
- 언어 변경 때문에 캐릭터 저장 데이터와 전투 로직이 깨지지 않는다.
- 출처와 버전이 다른 동일 계열 콘텐츠를 구분할 수 있다.

### 비용

- 모든 UI와 로그를 처음부터 번역 키로 작성해야 한다.
- 콘텐츠 팩 manifest, 의존성, 충돌과 버전 검증이 필요하다.
- 한국어 번역 용어집과 문체 기준을 관리해야 한다.
- 출처 팩을 추가할 때 실행 기능뿐 아니라 한국어 리소스도 함께 완성해야 한다.

이 비용은 나중에 하드코딩된 이름과 규칙을 분리하는 것보다 작다.

## 구현 원칙 요약

1. 기본 규칙 세트는 `dnd5e-2024`다.
2. 기본 로케일은 `ko-KR`이다.
3. 새 공식 서적은 개발자 관리 출처 팩으로 추가한다.
4. 캐릭터와 전투 데이터는 번역된 이름이 아니라 고정 콘텐츠 ID를 사용한다.
5. 규칙 로직, 출처 데이터, 번역 리소스를 분리한다.
6. 캠페인은 활성 출처 팩과 버전을 명시적으로 저장한다.
7. 한국어를 우선 완성하되 코드와 UI는 다른 언어를 수용할 수 있게 만든다.
