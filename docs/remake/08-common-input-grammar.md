## 1. 목표

RVTT의 탐험, 전투, DM 판정과 씬 편집은 기능은 달라도 같은 입력 문법을 사용한다.

사용자는 새로운 도구나 상황을 만났을 때도 다음 세 가지를 즉시 이해할 수 있어야 한다.

```text
Q
→ 취소, 거절 또는 한 단계 뒤로

E
→ 승인, 확정, 실행 또는 상호작용

1 2 3 4 5
→ 현재 상황에서 가장 중요한 다섯 개 이하의 행동
```

입력은 개별 스크립트에서 물리 키를 직접 확인하지 않는다. 먼저 `취소`, `승인`, `상황 행동 1`과 같은 의미 동작으로 정의하고 기본 키를 연결한다.

이 구조를 사용하면 이후 키 재설정이나 다른 입력 장치를 지원해도 게임의 조작 의미는 유지된다.

---

## 2. 핵심 입력 의미

### 2.1 Q: 취소, 거절과 뒤로

Q는 현재 입력 문맥에서 가장 가까운 미완성 작업 하나만 취소한다.

한 번의 Q 입력으로 여러 단계가 연속해서 닫히지 않는다.

우선순위 예시:

```text
현재 그리고 있는 미완성 벽이 있음
→ 벽 미리보기만 취소
→ 벽 배치 모드는 유지

배치 모드에서 미완성 작업이 없음
→ 배치 모드 종료
→ 선택 모드로 복귀

DM 승인 요청이 열려 있음
→ 요청 거절

전투 대상 지정 중
→ 대상 지정 취소
→ 이전 행동 선택 상태로 복귀
```

Q는 파괴적인 행동을 확정하는 데 사용하지 않는다.

### 2.2 E: 승인, 확정과 실행

E는 현재 입력 문맥에서 가장 우선순위가 높은 유효 행동을 승인하거나 확정한다.

예시:

```text
DM 승인 요청이 열려 있음
→ 요청 승인

다단계 편집 도구가 최종 확인을 기다림
→ 현재 결과 확정

상호작용 가능한 대상에 초점이 있음
→ 상호작용 실행

전투 행동의 대상과 조건이 모두 정해짐
→ 행동 실행 요청
```

공간을 직접 지정하는 클릭과 드래그는 그대로 사용한다. E는 모든 마우스 클릭을 대체하지 않으며, 명시적인 승인과 최종 확정이 필요한 단계의 공통 키다.

유효한 E 동작이 없으면 아무 행동도 실행하지 않는다.

### 2.3 1–5: 상황 행동 슬롯

숫자 1부터 5까지는 현재 상황에서 자주 사용하는 행동을 빠르게 선택하거나 실행하는 슬롯이다.

화면에는 항상 현재 의미를 표시한다.

```text
[1 이동] [2 회전] [3 스케일] [4 스포이드] [5 복제]
```

또는 상황에 따라:

```text
[1 주문 방식] [2 대상 방식] [3 범위] [4 피해 적용] [5 세부 정보]
```

정확한 슬롯 내용은 모드마다 달라질 수 있지만 다음 규칙은 유지한다.

- 현재 화면에 표시되지 않은 숨은 숫자 단축키를 만들지 않는다.
- 같은 시스템 안에서는 가능한 한 같은 슬롯 위치를 유지한다.
- 사용할 수 없는 슬롯은 다른 행동으로 갑자기 바꾸지 않고 비활성 상태로 표시할 수 있다.
- 다섯 개보다 적으면 남는 슬롯은 비워 둔다.
- 여섯 개 이상이 필요하면 가장 중요한 다섯 개만 직접 배치하고 나머지는 패널이나 하위 메뉴에 둔다.
- 슬롯 이름과 아이콘은 입력 문맥이 바뀌는 즉시 갱신한다.

1–5는 단순한 아이템 핫바가 아니라 RVTT 전체가 공유하는 `상황 행동 바`다.

## 3. 입력 문맥 우선순위

같은 키에 여러 행동이 걸리지 않도록 입력 문맥을 스택으로 관리한다.

높은 우선순위부터:

```text
1. 텍스트 입력과 수치 입력
2. 승인, 경고와 선택 요청 같은 모달 문맥
3. 현재 진행 중인 드래그, 대상 지정과 다단계 도구
4. 현재 모드: 선택, 배치, 전투 행동, 탐험
5. 전역 카메라와 일반 단축키
```

가장 위의 문맥이 입력을 처리하면 아래 문맥으로 전달하지 않는다.

예를 들어 DM이 씬 편집 중이어도 마법 승인 요청이 떠 있다면:

```text
E
→ 마법 승인
→ 배치 중인 오브젝트는 확정하지 않음

Q
→ 마법 거절
→ 편집 모드는 취소되지 않음
```

승인 요청이 닫힌 다음에야 Q와 E가 다시 씬 편집 문맥에 적용된다.

## 4. 씬 편집에서의 적용

### 4.1 배치 모드

```text
배치 대기 상태에서 Q
→ 배치 모드 종료
→ 선택 모드로 복귀

벽, 바닥 또는 영역을 만드는 중 Q
→ 현재 미완성 결과만 취소
→ 같은 배치 모드는 유지

최종 확인 단계에서 E
→ 현재 결과 확정

배치 완료 후
→ 같은 대상의 다음 고스트 유지
→ Q로 배치 모드를 끝낼 때까지 연속 배치
```

클릭이나 드래그만으로 완결되는 프리팹과 벽은 해당 마우스 조작으로 배치한다. E는 별도의 최종 승인 단계가 있는 도구에서 사용한다.

### 4.2 3차원 선택 박스

```text
마우스 드래그
→ XZ 범위 지정

마우스 놓기
→ 포인터 잠금
→ 상대 마우스 이동으로 Y 범위 지정

E
→ 선택 박스 확정

Q
→ 현재 선택 박스 취소
```

선택 포함 판정은 사용자 프리퍼런스의 `교차 선택` 또는 `완전 포함 선택`을 따른다.

### 4.3 기즈모와 인스펙터

- Shift 유지: 이동, 회전과 스케일 스냅 임시 해제
- Q: 현재 기즈모 드래그나 확정 전 인스펙터 변경 취소
- E: 현재 수치 입력 또는 확정 대기 중인 변형 적용
- 텍스트 또는 수치 입력란에 초점이 있으면 Q, E와 1–5를 일반 문자 입력으로 처리하며 게임 단축키를 실행하지 않는다.

## 5. DM 승인 요청에서의 적용

플레이어 행동이 DM 확인을 요구하면 DM 화면에 승인 문맥을 가장 높은 우선순위로 표시한다.

기본 입력:

```text
E
→ 승인

Q
→ 거절
```

추가 판정 선택지가 있다면 1–5에 표시한다.

예시:

```text
[1 그대로 승인]
[2 수정 후 승인]
[3 주사위 판정 요구]
[4 정보 보기]
[5 규칙 근거 보기]

E 승인    Q 거절
```

단, E의 기본 의미는 항상 현재 선택된 결과의 승인이다. 숫자 입력만으로 위험하거나 되돌리기 어려운 결과를 즉시 실행하지 않고, 필요한 경우 선택 후 E로 확정한다.

승인 요청에는 반드시 다음을 함께 보여준다.

- 요청한 플레이어와 캐릭터
- 행동 또는 마법 이름
- 대상과 범위
- 필요한 자원
- 자동 판정 결과
- DM이 확인해야 하는 예외
- `E 승인`과 `Q 거절` 표시

---

## 6. 마우스와 보조 키

### 왼쪽 마우스 버튼

- 대상과 위치 지정
- 선택
- 배치
- 드래그
- 기즈모 조작

### 오른쪽 마우스 버튼

- 카메라 회전과 카메라 조작에 우선 사용
- 승인이나 취소의 공통 키로 사용하지 않음

### Shift

- 현재 조작의 스냅을 누르고 있는 동안만 해제
- 이동, 회전, 스케일, 배치, 측정과 선택 보조에 동일하게 적용

### Ctrl

Ctrl은 보조 조작과 조합 단축키에 사용한다.

현재 확정된 예시:

- `Ctrl + 수직 마우스 이동`: 씬 편집 가상 격자와 배치 고스트의 Y 조절
- `Ctrl + D`: 선택 대상을 소스로 복제 배치 모드 진입

Ctrl 자체에 하나의 전역 행동을 강제로 지정하지 않는다.

## 7. 상황 행동 바 UI

1–5 입력은 화면의 상황 행동 바와 반드시 연결된다.

기본 위치는 하단 중앙 또는 하단 퀵 바 가까이로 둔다.

각 슬롯은 다음을 표시한다.

```text
숫자
아이콘
행동 이름
현재 상태
필요 시 남은 횟수나 자원
```

상태 예시:

- 사용 가능
- 선택됨
- 비활성
- 승인 필요
- 재사용 대기
- 추가 입력 필요

Q와 E도 현재 문맥의 의미를 짧게 표시한다.

```text
Q 배치 종료    E 선택 확정
```

또는:

```text
Q 거절    E 승인
```

사용자가 키의 의미를 추측하게 만들지 않는다.

## 8. 구현 구조

입력은 개별 기능이 `UserInputService`에서 키를 직접 감시하는 방식으로 흩어지지 않는다.

공통 책임 후보:

- `InputRouterService`: 물리 입력을 의미 동작으로 변환
- `InputContextService`: 문맥 스택과 우선순위 관리
- `InputBindingService`: 기본 키와 사용자 재설정 관리
- `ContextActionBarService`: 1–5와 Q·E의 현재 의미 표시
- `ModalActionService`: 승인과 거절 요청의 입력 독점

의미 동작 후보:

```text
Cancel
Confirm
ContextAction1
ContextAction2
ContextAction3
ContextAction4
ContextAction5
TemporarySnapBypass
SecondaryModifier
PrimaryPointer
CameraPointer
```

각 문맥은 자신이 처리할 의미 동작만 등록하고, 종료될 때 반드시 해제한다.

서버가 권한과 실제 실행 가능 여부를 검증하며, 클라이언트 입력만으로 DM 승인이나 게임 상태 변경을 확정하지 않는다.

---

## 9. 확정하는 방향

1. ESC를 핵심 게임 입력으로 사용하지 않는다.
2. Q는 취소, 거절과 한 단계 뒤로의 공통 의미다.
3. E는 승인, 확정, 실행과 상호작용의 공통 의미다.
4. 1–5는 현재 문맥에서 가장 중요한 행동을 표시하고 실행하는 상황 행동 슬롯이다.
5. Q와 E는 가장 높은 활성 입력 문맥 하나에서만 처리된다.
6. 미완성 작업이 있을 때 Q는 그 작업만 취소하고 모드를 유지한다.
7. 미완성 작업이 없는 배치 모드에서 Q는 선택 모드로 돌아간다.
8. DM 승인 요청이 열리면 E 승인과 Q 거절이 다른 문맥보다 우선한다.
9. Shift는 현재 조작의 스냅을 임시로 해제한다.
10. 오른쪽 마우스 버튼은 카메라 조작에 우선 사용한다.
11. 현재 키 의미는 항상 화면에 표시한다.
12. 키를 직접 하드코딩하지 않고 의미 동작과 입력 문맥으로 구현한다.

---

## 10. 후속 논의 항목

1. 선택 모드의 1–5 기본 슬롯
2. 배치 모드의 1–5 기본 슬롯
3. 탐험과 전투의 1–5 행동 분류
4. E 상호작용과 전투 확정이 겹칠 때의 세부 우선순위
5. Q를 길게 눌렀을 때 전체 모드 종료 기능을 둘지 여부
6. 키 재설정 지원 범위와 필수 고정 키 여부
7. 게임패드와 모바일에서 Q, E와 1–5를 대응하는 방식
