## 1. 범위

이 문서는 씬 편집기의 단축키 표가 아니라 **RVTT 전체의 입력 교과서**다.

적용 범위:

- 플레이어 탐험
- 전투 행동과 대상 지정
- 주문과 능력 사용
- DM 승인, 거절과 판정
- 토큰과 오브젝트 상호작용
- 씬 편집
- 모달, 경고와 수치 입력

모든 화면이 같은 키를 모두 사용해야 한다는 뜻은 아니다. 각 문맥은 필요한 의미 입력만 활성화한다.

핵심 원칙:

```text
Q
→ 취소, 거절 또는 한 단계 뒤로

E
→ 승인, 확정, 실행 또는 상호작용

1 2 3 4 5
→ 플레이와 DM 진행에서 사용하는 주요 행동 슬롯
```

`1–5`는 RVTT 전체에서 사용할 수 있는 공통 행동 슬롯이지만, **모든 모드가 반드시 채워야 하는 슬롯은 아니다.**

씬 편집기는 기본적으로 `1–5`를 사용하지 않는다.

---

## 2. 물리 키와 의미 동작을 분리한다

기능 코드가 Q, E 또는 숫자 키를 직접 감시하지 않는다.

먼저 다음과 같은 의미 동작을 정의한다.

```text
Cancel
Confirm
Interact
PrimaryAction1
PrimaryAction2
PrimaryAction3
PrimaryAction4
PrimaryAction5
TemporarySnapBypass
SecondaryModifier
PrimaryPointer
CameraPointer
```

기본 키 연결:

```text
Q → Cancel
E → Confirm 또는 Interact
1–5 → PrimaryAction1–5
Shift → TemporarySnapBypass
```

현재 문맥이 같은 E를 `Confirm`으로 쓸지 `Interact`로 쓸지 결정한다.

이 구조를 사용하면 키 재설정, 게임패드, 접근성 입력을 추가해도 게임의 입력 의미가 유지된다.

---

## 3. Q: 취소, 거절과 한 단계 뒤로

Q는 현재 입력 문맥에서 가장 가까운 미완성 상태 하나만 취소한다.

한 번의 Q 입력으로 여러 단계가 연속해서 닫히지 않는다.

예시:

```text
전투 대상 지정 중
→ 대상 지정만 취소
→ 행동 선택 상태로 복귀

주문 범위 조정 중
→ 현재 범위 조정만 취소
→ 주문 선택 상태로 복귀

DM 승인 요청 표시 중
→ 요청 거절

미완성 벽을 그리는 중
→ 현재 벽 미리보기만 취소
→ 벽 배치 모드는 유지

배치 대기 상태
→ 배치 모드 종료
→ 선택 모드로 복귀
```

Q는 파괴적인 작업을 승인하는 용도로 사용하지 않는다.

현재 취소할 상태가 없으면 아무 행동도 하지 않는다.

---

## 4. E: 승인, 확정, 실행과 상호작용

E는 현재 입력 문맥에서 가장 우선순위가 높은 유효 행동을 승인하거나 실행한다.

예시:

```text
DM 승인 요청 표시 중
→ 요청 승인

전투 행동의 대상과 조건이 모두 정해짐
→ 행동 실행 요청

상호작용 가능한 대상에 초점이 있음
→ 상호작용 실행

다단계 편집 도구가 최종 확인을 기다림
→ 결과 확정
```

E는 모든 마우스 클릭을 대체하지 않는다.

- 위치 선택과 대상 지정은 마우스를 사용할 수 있다.
- 클릭이나 드래그만으로 완결되는 편집 작업은 해당 조작으로 완료할 수 있다.
- 별도의 승인이나 최종 확정이 필요한 단계에서 E를 사용한다.

유효한 E 동작이 없으면 아무 행동도 실행하지 않는다.

---

## 5. 1–5: RVTT 주요 행동 슬롯

숫자 1부터 5까지는 플레이와 DM 진행 중 자주 사용하는 행동을 빠르게 선택하는 공통 슬롯이다.

주요 사용처:

- 플레이어의 전투 행동과 자주 쓰는 능력
- 탐험 중 자주 쓰는 상호작용과 도구
- 선택한 토큰의 주요 행동
- DM이 조종하는 NPC의 주요 행동
- DM 승인 요청의 추가 선택지
- 현재 진행 단계의 핵심 판정 선택지

예시:

```text
[1 이동] [2 행동] [3 추가 행동] [4 반응] [5 기타]
```

또는 선택한 주문이나 능력에 따라:

```text
[1 기본 시전] [2 상위 슬롯] [3 대상 변경] [4 정보] [5 취소 전 단계]
```

세부 슬롯 구성은 전투와 행동 시스템을 설계할 때 확정한다.

### 5.1 슬롯 사용 규칙

- 현재 화면에 의미가 표시되지 않은 숨은 숫자 단축키를 만들지 않는다.
- 같은 시스템에서는 가능한 한 같은 슬롯 위치를 유지한다.
- 사용할 수 없는 슬롯은 비활성 상태로 남길 수 있다.
- 행동이 다섯 개보다 적으면 남는 슬롯을 비워 둔다.
- 여섯 개 이상이 필요하면 핵심 다섯 개만 직접 표시하고 나머지는 메뉴에 둔다.
- 위험하거나 되돌리기 어려운 결과는 숫자 입력만으로 즉시 확정하지 않고 필요하면 E 승인을 거친다.

### 5.2 숫자 슬롯을 쓰지 않는 문맥

문맥에 숫자 행동이 필요하지 않으면 `1–5`를 활성화하지 않는다.

대표적으로 씬 편집은 기본적으로 숫자 슬롯을 사용하지 않는다.

```text
씬 편집
→ 도구 팔레트와 퀵 바에서 도구 선택
→ 마우스, Q, E와 보조키로 조작
→ 1–5는 비어 있으며 편집 도구가 임의로 점유하지 않음
```

새 씬 편집 모듈도 자체적으로 `1–5`를 가져갈 수 없다. 향후 편집기에 숫자 슬롯이 정말 필요해지면 전역 입력 교과서 수준에서 별도로 결정한다.

## 6. 입력 문맥 스택

같은 키가 여러 기능을 동시에 실행하지 않도록 활성 문맥을 스택으로 관리한다.

높은 우선순위부터:

```text
1. 텍스트, 검색과 수치 입력
2. 승인, 경고와 선택 요청 같은 모달
3. 진행 중인 드래그, 대상 지정과 다단계 작업
4. 현재 주요 모드: 전투, 탐험, DM 진행, 씬 편집
5. 전역 카메라와 일반 단축키
```

가장 위의 문맥이 입력을 처리하면 아래 문맥으로 전달하지 않는다.

예를 들어 DM이 씬을 편집하던 중 플레이어의 마법 승인 요청이 도착하면:

```text
E
→ 마법 승인
→ 편집 결과는 확정되지 않음

Q
→ 마법 거절
→ 편집 모드는 종료되지 않음
```

승인 요청이 닫힌 뒤에야 Q와 E가 다시 씬 편집 문맥에 적용된다.

---

## 7. DM 승인 요청

플레이어 행동이 DM 확인을 요구하면 DM 화면에 승인 문맥을 높은 우선순위로 표시한다.

기본 입력:

```text
E → 승인
Q → 거절
```

추가 선택지가 필요한 경우에만 1–5를 사용한다.

예시:

```text
[1 그대로 처리]
[2 수정 후 처리]
[3 주사위 판정 요구]
[4 세부 정보]
[5 규칙 근거]

Q 거절    E 현재 선택 승인
```

승인 요청에는 최소한 다음 정보를 보여준다.

- 요청한 플레이어와 캐릭터
- 행동 또는 마법 이름
- 대상과 범위
- 필요한 자원
- 자동 판정 결과
- DM이 확인해야 하는 예외
- 현재 Q와 E의 의미

서버가 요청 상태와 DM 권한을 검증한다. 클라이언트의 E 입력만으로 승인 상태를 임의 변경하지 않는다.

---

## 8. 씬 편집에서의 적용

씬 편집은 공통 Q와 E 의미를 사용하지만 `1–5` 행동 바를 사용하지 않는다.

### 8.1 배치 모드

```text
미완성 벽, 바닥 또는 영역 작업 중 Q
→ 현재 미완성 결과만 취소
→ 같은 배치 모드는 유지

배치 대기 상태에서 Q
→ 배치 모드 종료
→ 선택 모드로 복귀

최종 확인을 기다리는 도구에서 E
→ 현재 결과 확정
```

클릭이나 드래그만으로 완결되는 배치는 E를 추가로 요구하지 않는다.

### 8.2 3차원 선택 박스

```text
마우스 드래그
→ XZ 범위 지정

마우스 놓기
→ 포인터 잠금
→ 상대 마우스 이동으로 Y 범위 지정

E
→ 선택 박스 확정

Q
→ 선택 박스 취소
```

선택 포함 판정은 사용자 프리퍼런스의 `교차 선택` 또는 `완전 포함 선택`을 따른다.

### 8.3 기즈모와 인스펙터

- Shift 유지: 이동, 회전과 스케일 스냅 임시 해제
- Q: 현재 확정 전 변형을 취소
- E: 명시적인 확정 대기 상태가 있을 때만 적용
- 숫자 입력란에 초점이 있으면 Q와 E를 일반 문자 입력으로 처리하고 게임 단축키를 실행하지 않는다.

씬 편집 도구 모듈은 공통 입력 라우터에 의미 동작만 등록하며 물리 키를 직접 감시하지 않는다.

---

## 9. 마우스와 보조키

### 왼쪽 마우스 버튼

- 선택
- 위치와 대상 지정
- 배치
- 드래그
- 기즈모 조작

### 오른쪽 마우스 버튼

- 카메라 회전과 카메라 조작에 우선 사용
- 승인이나 취소의 공통 입력으로 사용하지 않는다.

### Shift

- 현재 편집 조작의 스냅을 누르고 있는 동안만 해제한다.
- 이동, 회전, 스케일, 배치와 측정에 같은 의미를 적용한다.

Shift의 다른 게임 플레이 용도는 해당 문맥에서 별도로 정의할 수 있지만, 한 문맥에서 두 의미가 충돌하지 않게 한다.

### Ctrl

Ctrl은 조합 단축키와 보조 조작에 사용한다.

현재 확정된 씬 편집 예시:

- `Ctrl + 수직 마우스 이동`: 가상 격자와 배치 고스트의 Y 조절
- `Ctrl + D`: 선택 대상을 소스로 복제 배치 모드 진입

Ctrl 자체에 하나의 전역 행동을 강제로 지정하지 않는다.

---

## 10. 입력 안내 UI

현재 활성 문맥의 Q와 E 의미를 화면에 짧게 표시한다.

예시:

```text
Q 대상 지정 취소    E 행동 실행
```

```text
Q 거절    E 승인
```

```text
Q 배치 종료
```

1–5가 활성화된 플레이 또는 DM 문맥에서는 행동 바를 표시한다.

각 슬롯은 다음 정보를 가질 수 있다.

- 숫자
- 아이콘
- 행동 이름
- 사용 가능 상태
- 남은 횟수나 자원
- 승인 필요 여부

씬 편집에서는 숫자 행동 바를 숨기고 편집 도구 팔레트와 현재 도구 안내를 표시한다.

## 11. 구현 구조

공통 책임:

- `InputRouterService`: 물리 입력을 의미 동작으로 변환
- `InputContextService`: 활성 문맥 스택과 우선순위 관리
- `InputBindingService`: 기본 키와 사용자 키 재설정 관리
- `InputHintService`: 현재 Q, E와 보조 입력 의미 표시
- `PrimaryActionBarService`: 활성 문맥이 제공하는 1–5 행동 표시
- `ModalActionService`: 승인과 거절 요청의 입력 독점

각 문맥은 자신이 처리할 의미 동작만 등록하고 종료될 때 반드시 해제한다.

```text
탐험 문맥
→ Interact와 필요 시 PrimaryAction1–5 등록

전투 행동 문맥
→ Cancel, Confirm과 PrimaryAction1–5 등록

DM 승인 문맥
→ Cancel, Confirm과 필요 시 PrimaryAction1–5 등록

씬 편집 문맥
→ Cancel, Confirm과 편집 보조 동작 등록
→ PrimaryAction1–5는 등록하지 않음
```

---

## 12. 확정하는 방향

1. 이 문서는 씬 편집이 아니라 RVTT 전체의 입력 교과서다.
2. ESC를 핵심 게임 입력으로 사용하지 않는다.
3. Q는 취소, 거절과 한 단계 뒤로의 공통 의미다.
4. E는 승인, 확정, 실행과 상호작용의 공통 의미다.
5. 1–5는 플레이와 DM 진행에서 사용하는 주요 행동 슬롯이다.
6. 모든 문맥이 1–5를 사용할 필요는 없다.
7. 씬 편집기는 기본적으로 1–5를 사용하지 않으며 편집 모듈도 이를 임의로 점유하지 않는다.
8. 현재 Q, E와 활성화된 1–5의 의미는 화면에 표시한다.
9. 가장 높은 활성 입력 문맥 하나만 입력을 처리한다.
10. 물리 키를 기능 코드에 하드코딩하지 않고 의미 동작과 입력 문맥으로 처리한다.
11. 서버가 권한, 자원과 실제 실행 가능 여부를 검증한다.

---

## 13. 후속 논의 항목

1. 탐험 상태의 기본 1–5 구성
2. 전투 상태의 기본 1–5 구성
3. 선택한 토큰과 캐릭터에 따른 슬롯 변경 규칙
4. DM 승인 요청에서 숫자 선택지를 제공하는 조건
5. 플레이어와 DM의 입력 안내 UI 위치
6. 사용자 키 재설정 가능 범위
7. 게임패드와 모바일 입력 대응
